# ADR-001 · 图用 Mermaid 写在 Markdown 里

**状态**：已采用
**日期**：2026-11-17

> **后续（不改变本条决定）**：图的张数已从 6 张增到 8 张（见 `01-图.md`）；本条说的「总览那张最挤」现在指 `README.md` 里那张 mermaid 总览图，不在 `01-图.md` 里。**「用 Mermaid 写在 Markdown 里、不用图片、不用外部 HTML」这个决定不变。**

## 背景

这套设计需要六张图：门禁链、状态机、对象关系、时序、阶段流程、准入退化。有三种存法：

1. 导出成 PNG 或 SVG 放进仓库；
2. 用 Archify 之类工具渲染成自包含 HTML；
3. 用文本格式（Mermaid、D2、PlantUML）写在 Markdown 里。

仓库里三种都有先例：`02-流程图/1201版本-Astra融合/` 是 Archify 产的 HTML，`src/present/archify.ts` 会把图结构搬成 Archify 候选。

## 决定

**用 Mermaid 写在 Markdown 里。** 不用图片，也不用外部 HTML。

## 理由

1. **GitHub 原生渲染。** 这套设计的目标之一是「可以发到 GitHub」，而 GitHub 会渲染 Markdown 里的 Mermaid。图片要另外打开，HTML 在 GitHub 上看不了。
2. **文本可 diff。** 改图能看出改了哪一行。图片改了只能看出「换了」。
3. **图不会被导出成一张没人能改的 PNG。** 这个仓库的历史里出现过「只留 HTML 让图不可复现」的问题，仓库的常驻纪律文件（未收录进本包）专门有一条：「重新渲染后要把候选与 HTML 一起复制回该目录，只留 HTML 会让图不可复现」。Mermaid 从根本上没有这个问题。
4. **不引入工具链依赖。** 不需要装渲染器，不需要构建步骤。

## 后果

**换来的**：图与正文在同一个文件里，改一处不会漏改另一处；任何人 clone 下来就能看；GitHub 的 PR 页面里图会跟着渲染。

**放弃的**：Mermaid 的布局控制弱，复杂图会挤。六张图里「总览」那张最挤，已经用左右分区压缩过。如果将来要更精细的布局，可以另存一份 Archify 版放在 `02-流程图/`，但**Markdown 里的 Mermaid 是权威版**，Archify 版是派生物。

**一条约束**：图里不写实现细节。图上出现函数名、字段全名、具体命令，说明图画错了——那些属于正文。
