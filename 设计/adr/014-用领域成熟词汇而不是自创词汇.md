# ADR-014 · 用领域成熟词汇，不自创

**状态**：已采用
**日期**：2026-11-18

## 背景

外部审计指出门 3（有牙实验）有一个实质错误：把实现改出语法错误，判据会红；还原后绿；于是这条判据被标记为「有牙」——**但它对真正的业务错误毫无反应**。

我第一次的修法是：给判据加一个 `assertionId` 字段，要求「红的必须是目标断言」。

**这个修法是表面的。** 理由：判据作者只要声明一条错断言，规则就在他自己的声明范围内成立——**自证**。而且我没有回答「如果判据本身就是空心的怎么办」。

后来去查了变异测试（mutation testing）领域的做法，发现这个问题已经有十几年的成熟答案，而且词汇表是现成的：

| 领域里已有的概念 | 我原来自己造的东西 |
|---|---|
| PIT `DetectionStatus`：`KILLED` / `SURVIVED` / `TIMED_OUT` / `RUN_ERROR` / `NO_COVERAGE` | 我只有「有牙 / 无牙 / 未能验证」三个词 |
| Stryker mutant states：加了 `CompileError` / `RuntimeError`，并明确它们「不是 viable mutant」 | 我把语法错误混进了「红」 |
| **hollow assertion**（空心断言）：`assert x is not None`、`assert len(x) >= 0`、`assert isinstance(x, T)` 这类有断言但无区分力的写法，有可 grep 的检测模式 | 我完全没想到判据本身可能是空心的 |
| **checked coverage**：覆盖率要「被检查过」才算数 | 我只算覆盖率 |
| 「Each assertion must be FALSIFIABLE by a realistic bug」 | 我只有「判据必须能红」 |

**我造的那三个词，恰好把领域里已经分清的东西又混在一起了。**

## 决定

**遇到已有成熟做法的领域，必须先用领域词汇，不许自创；自创的术语必须在 ADR 里说明「为什么现成的不能用」。**

三条落地：

1. **优先查领域词汇**。设计一个机制之前，先查这个机制在对应学科里叫什么、状态怎么分、边界怎么定。
2. **直接搬状态词汇**，包括它的分歧。门 3 现在用 PIT / Stryker 的八个状态（`killed` / `survived` / `no-coverage` / `compile-error` / `runtime-error` / `timeout` / `red-wrong-assertion` / `restore-failed`），后两个是本设计补的，已标注。
3. **分歧如实写，不装作统一**。`timeout` 在 PIT 里计入 detected，在 Stryker 里是 inconclusive。本设计采用第三种取舍（单列、两边都不算），并在规格里写明为什么。

## 理由

**一，自创词汇的第一个代价是丢失已有的边界。** 领域里分 `compile-error` 与 `runtime-error` 与 `timeout` 三档，是因为这三者的**证据价值不同**：前两者不是关于测试的证据，后者是「可能有也可能没有」。我原来的「红 / 绿」两分把三档全压成一档，所以语法错误能冒充有牙。

**二，自创词汇的第二个代价是读者无法对照。** 一个做过 mutation testing 的人看到「有牙 / 无牙」，得重新学一遍；看到 `killed` / `survived`，他立刻知道边界在哪。

**三，这个毛病在本设计里不是第一次。** 同一个形状的错误出现过四次：

| 次数 | 自创的东西 | 领域里已有的 |
|---|---|---|
| 1 | 「有机制覆盖」 | 机制覆盖率 / enforcement 分类 |
| 2 | 「证据强度四档」 | 证据等级（GRADE、牛津证据等级）里对「实测 / 定性」的区分 |
| 3 | 「有牙 / 无牙」 | mutation testing 的 mutant states |
| 4 | 「满足 / 违反 / 材料不足」 | Kleene 三值逻辑的 `T` / `F` / `U`，以及「第三值必须有契约定义」的论证 |

**四次都是「先造词，后补依据」，而正确的顺序是反的。**

## 后果

**换来的**：门 3 从「两分」变成「八态」，能区分「判据没牙」与「判据空心」与「改坏方式无效」——这是审计那个价格反例能被正确判定的唯一办法。

**放弃的**：词汇变得专业，没做过变异测试的人要查一次。**这个成本必须付**，因为另一条路是让人在不懂边界的情况下用一套看起来简单的词。

**一条自我约束**：以后写任何新机制，先在规格里写一句「这一节用的是 ____ 领域的 ____ 做法」，填不出来就说明我在自创。

**适用范围**：这条 ADR 不适用于**本设计自己特有的对象**（契约、门、投影、三档准入）——那些领域里确实没有现成词汇。它适用于**通用机制**（测试有效性、证据等级、三值判定、审计日志完整性）。
