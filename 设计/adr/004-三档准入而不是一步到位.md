# ADR-004 · 三档准入，不是一步到位

**状态**：已采用
**日期**：2026-11-17

> **后续（不改变本条决定）**：本条列的四个「无依据」阈值里，覆盖率 60% 的含义已从「低于就拒绝出图」改成「完整图的门槛」；拒绝出图的门槛是 30%，并且 30%–60% 之间要出二档图（见 `08-失效链.md` 链 C）。**三档准入与「按机械信号升级」这个决定不变。**

## 背景

这套设计的完整形态要求：一份意图、一份约束、若干契约、每条判据要写要冻要做有牙实验、一份投影、一份交接包。

这套东西的前期成本很高，而**「前期成本能不能换回后期收益」这件事，本项目的全部调研里没有任何数据**。

两难：

- 要求一步到位：大多数人在看到收益之前就放弃了。
- 允许随时不做：机制永远建不起来，退化成「有空再说」。

## 决定

**分三档，按机械信号升级。**

| 档 | 要建什么 | 升级信号 |
|---|---|---|
| T0 草稿档 | 意图 + 一条冒烟命令 | 同一 bug 修两次，或改 A 弄坏 B |
| T1 门禁档 | 加约束 + 判据冻结 + 有牙 + 越界拦截 | 契约数超过 8，或换人接手 |
| T2 契约档 | 加切契约 + 投影 + 交接包 | 不升级。T2 是终点 |

三个信号都能机械判：同一文件同一处两次提交 diff 相似度超阈值、A 被改后 B 的判据变未通过、直接数契约个数、交接包里出现第二个签字人。

## 理由

1. **承认未验证项，而不是掩盖它。** 前期开销的回本期没有数据，所以不能要求用户先信。T0 的实际开销是 10 分钟三个文件一条命令——这个成本低到不需要论证。
2. **升级必须由信号触发，不能由感觉触发。** 「感觉需要流程了」不是一个可以被复现的判断，而三个信号都能。
3. **降级路径同样重要。** 项目停止维护超过一个迭代周期，应当退回 T0 并标明「停止维护」。留着 T2 的全套产物假装还在跑，比降级更糟。

## 后果

**换来的**：零成本起步；成本随收益增长；升级时机可复现。

**放弃的**：三档之间有一致性代价。T0 档没有契约，所以没有投影，所以也没有覆盖率——**从 T0 升到 T1 时，项目会突然多出一批从未被认领的孤儿代码**。这是正常的，孤儿清单第一次出现时会很长。

**四个阈值没有任何依据**：覆盖率下限 60%、判据有效期 90 天、契约数上限 8、重切次数上限 3。它们是工程约定，全部集中在 `thresholds.json`，改任何一条必须写决策记录。**明写「无依据」比假装有依据好。**

**一条不许违反的规则**：升级与降级都要留痕。降级不写记录，下一次就会有人以为还在 T2。
