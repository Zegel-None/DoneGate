# ADR-010 · 任何判据必须带基线，否则绝对阈值没有意义

**状态**：已采用
**日期**：2026-11-18

## 背景

[06-验证方案.md](../06-验证方案.md) 的 V1 原本有一条判据：「拦对命中率 ≥ 50%」。命中率的定义是：被门禁拦下的提交里，其改动文件在随后若干次提交内被再改过的比例。

直觉是「被拦的提交确实更容易返工」，所以这个比例高就说明拦对了。

试跑（本仓库 71 次提交）的结果：

| | 比例 |
|---|---|
| 被拦的 32 次提交 | 26 / 32 = **81%** |
| 没被拦的 39 次提交（基线） | 33 / 39 = **85%** |
| 差值 | **−3.4 个百分点** |

**81% 远高于 50% 的判据，看上去完美通过；但基线是 85%，这个指标一点区分力都没有。** 它测的是「一个 71 次提交的仓库里文件被反复改的速度」，不是「门禁拦得对不对」。

## 决定

**任何判据，如果是比例或均值，必须同时给出一条基线，并以「与基线的差」为判据，不许用绝对阈值。**

三条落地：

1. 写判据时，若形如「X 比例 ≥ N%」，必须同时写「基线是 M%」与「要求差 ≥ K 个百分点」。
2. 没有合适基线的判据，必须换成绝对要求（如「3 人全部答对」）或直接删掉。
3. 已经写好的判据逐个回查。当前结果：V1 已改（只剩误拦率一条）、V2 已补基线（另取 20 条随手写的判据作对照）、V3 不需要（3/3 是绝对要求）、V4 与 V5 本来就有对照。

## 理由

**一，绝对阈值会被分布本身满足。** 只要指标与任务量的相关性大于与质量的相关性，阈值就会被「做得越多分越高」满足，与门禁好坏无关。

**二，这条错误我自己犯过两次。** 第一次是「挡住 ≥40」——那 40 是我设的，我改设计达到了它；第二次是这条命中率。**两次的共同形状是：先有想要的结论，再挑一个能被满足的指标。**

**三，基线是唯一能把「这有多好」变成「这比别人好多少」的东西。** 而后者才是判据该回答的问题。

## 后果

**换来的**：所有比例型判据都必须先找基线，找不到就换成绝对要求或删掉。这会砍掉一批看起来漂亮但无意义的指标。

**放弃的**：有些维度确实找不到基线（比如「误拦率」——没有一个「更松的门禁」可比）。这些维度只能靠人判，不能机器验。**V1 现在就是这种状态：只剩一条靠人判的判据。**

**一条自我约束**：以后再加判据，先问「它的基线是什么」。答不出来就不写这条判据。
