# 节点契约 · 写方路由

## 零、先读这段：这是纪律，不是门禁

你拿这份文件，通常是一轮活到了关口：要开工，要写判据，要收证据，或要交接。动手之前，先认清这套东西的性质。它没有钩子，没有拦截器，也没有替你采集证据的运行器。一轮工作要过的六道门（门 0 起手、门 1 基线、门 2 判据、门 3 有牙、门 4 证据、门 5 复核），每一道都只是你走到那一步必须自己回答的问题；答案由你来写，也只有靠你如实写。后文每一条「不许」，效力都到你的自觉为止。

下面几个词全篇反复出现，先各给一句人话解释。判据是一条能判断真假的命令，实际结果和事先写好的期望对得上才算过；判据失败叫红，通过叫绿。契约是一次可以独立验收的工作，有自己的代码范围和若干条判据。冻结指判据先写好、由人签字，实现过程中不许改；先写实现再补判据，等于让被检查的人自己出题。有牙指这条判据被故意改坏的实现真的弄红过；没红过的判据，判绿没有分量。写方是动手干活的一方，也就是读这份文件的你和你的 AI 会话。判方是另一个会话、另一个厂商的模型，复核时只看得见判据原文和运行输出，只答 pass、fail 或 unknown。总账是每轮收尾贴的一行状态统计。

三件它硬做不到的事，先说清楚，不许含糊。第一件，它做不到「状态只有一个来源」（INV-01，规格 §一「不变量」里的编号）：状态全靠你记录，没有任何机制防止你写错或写假；你能做的补救是每轮把总账贴出来，数字与命令输出一起贴。第二件，「判据必须能红」这条它强制不了：它只能要求你如实贴退出码，验不了你是不是改过输出；你能做的补救是把有牙实验真做一次，红的那次输出原样贴。第三件，它做不到「门禁拦得住」：你跳过任何一道门，不会有任何警报响起；你能做的补救是跳过哪道门就写一个 `skipReason`，写进文件里。

正因为它全靠自觉，经它得出的任何结论都要按 `../设计/adr/007-自评结论必须降一档并披露.md` 降一档采信。一句话概括它的能力上限：它让你少骗自己一点，压不住「假装做完了」。

## 一、四条不许（整份 skill 唯一绝对的话）

整份技能里只有这四条是绝对的话，其余内容都只是「走到哪一步、读哪张卡」的指引。

1. 不许把「流程走完了」说成「验收通过了」。判据跑完，状态只有五个词：未验证、通过、未通过、过期、无法判断。`通过` 之上没有更强的词；`通关` 是挂在通过上的一个标记，不是第六个状态。
2. 不许由写方推状态。状态从材料现算，材料摆在哪、算出哪个就是哪个；算不出来就写 `无法判断`，不许估、不许猜。
3. 不许改判据不重签。判据改一个字符就要重新签；没重签的判据，状态是 `无法判断`，不是 `过期`。例外（INV-15、§3.5 定案 A）：在「过期」状态下改写判据且未重签，状态转 `未验证`。四个状态别互相顶替。
4. 不许用 `|| true`、`continue-on-error`、只打 warn 的写法让判据变绿。命中这一条，直接判红。

## 三、一轮的固定动作（七步，与 `02-规格.md` §9.1 逐条对应）

一轮工作有七个固定动作，做完才算一轮。每步括号里的是时间预算。

1. 读 `INTENT.md`、`CONSTRAINTS.md` 和交接包（2 分钟）。`INTENT.md` 记这个项目为什么做、什么算成功；`CONSTRAINTS.md` 记不许碰什么、必须守什么；交接包是上一轮留给这一轮的交接文档。
2. 跑冒烟，确认基线绿（1 分钟）。冒烟是一条最快确认项目整体还活着的最小命令，基线是你动手之前项目已有的状态。冒烟红就先修基线，这一轮不接新活。
3. 只挑一个契约，不许多挑。
4. 跑该契约全部判据，拿真实退出码，按第五节的要求把结果落成证据。
5. 判方复核（5 分钟，怎么做见门 5 卡）。
6. 更新交接包与缺口清单（2 分钟）。缺口清单列的是项目当前欠的账，也就是还没做或已经烂掉的事；门 0 靠它判断这一轮挑的契约是不是该做的那一个。
7. **写决策记录**——只在这一轮改了判据、边界或意图时写（3 分钟）。它是一篇短文，说明改了什么、为什么改，留给后续轮次查。

第 3 步值得单独强调：一次会话一个契约，是这套东西里最省事又最有效的一条（§9.1 原话）。

## 四、五个状态词与六栏总账

每轮收尾，你要贴一句总账：一行字，报告这一轮的判据各落在什么状态。状态词与总账的定义不在本文件里，定义在 `../设计/02-规格.md` §三；`通过` 的四个子数在 §3.4.1，机器可读的权威是 `tools/classification.json`。

总账格式固定，逐字贴，不许改写：

```text
本轮 N 项：通过 A、未通过 C、未验证 D、过期 E、无法判断 F、不稳定 G
其中通过里：算数 A1、无牙 A2、未做实验 A3、待重验 A4
```

四个子数各指什么：`算数` 是可信的通过（做过有牙实验、也不用重验）；`无牙` 是跑绿但改坏实验暴露了判据没牙；`未做实验` 是跑绿但从没做过改坏实验；`待重验` 是跑绿但材料上游变了，结论要先重跑再信。

六栏相加必须等于 N（INV-16）。加不起来就是算错了，回头重算，不许凑。`不稳定` 是第六栏、占分母：同一条判据连续三次运行结果各不相同就归入这一栏；它不是五个状态词之外的附注，是一条要人去看的信号。

两行里的 `N`、`A`、`C`、`A1` 全是占位符，必须换成实数再贴。本轮 3 条判据全绿、三条都做过改坏实验时，总账该写成：

```text
本轮 3 项：通过 3、未通过 0、未验证 0、过期 0、无法判断 0、不稳定 0
其中通过里：算数 3、无牙 0、未做实验 0、待重验 0
```

照抄占位符等于没算。试点实测里，五轮连做的样本有 45/80 把 `N` 原样抄进了总账，那一行根本加不起来。

## 五、证据的最小要求

判据每跑一次，要留下三份文件才算证据：`start.json`（运行前记现场）、`report.json`（运行后记结果）、`end.json`（收尾记录）。三份文件互相哈希链：后一份里记着前一份的哈希，改了其中任何一份，后面的链就对不上。断任何一环，整份证据判 `无法判断`。

`report.json` 里的退出码必须是子进程直读的，不经任何包装层。你经 `npm` / `pnpm` / `npx` 跑判据时，取到的是包装层的退出码，不是判据本体的；包装层什么时候替换掉这个码，你控制不了，判据就变成装饰。（2026-11-19 复测过 7 条路径，没有复现「包装层把退出码吞成 0」；所以这条纪律的理由落在更稳的那句话上：问题从来不是「本机会吞」，是「哪一层的码不可控」。）

## 六、自检：这个仓库自己的四条

这个仓库（装着本技能与全部设计的档案库）自己带四条自检。你改了文档或工具之后，在仓库根目录把四条全跑一遍，四条都退出码 0 才算这一轮干净：

```text
node "tools/check-package.mjs"   结构与链接
node "tools/verify-spec.mjs"     规则本身
node "tools/check-rot.mjs"       文档腐化（13 条检查）
node "skill/check-plan.mjs"      派工单来源节号
```

但全绿只证明档案自洽，不证明设计有效。这句话写在 `../设计/adr/007-自评结论必须降一档并披露.md` 里。
