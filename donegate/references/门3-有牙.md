# 门 3 · 有牙

**这张卡判什么**：它判的不是「判据跑绿了」，而是「这条判据被故意改坏的实现真的弄红过没有」。没红过的判据，判绿没有分量。规则本体在 规格（调研/评审材料，不在公开分发包内） 的 §六 与 §6.1；本卡只写怎么操作、按什么顺序、什么算过。

## 入口条件

| 编号 | 条件 | 不满足时 |
|---|---|---|
| 1 | 门 2 已过：这条判据的三件套（`claim`、`observable`、`scope`）都已声明 | 回 [门 2](./门2-判据.md) 补齐三件套 |
| 2 | 手上有被测实现文件的路径，并且能算出它的内容哈希 | 先确定被测文件，再开始实验 |
| 3 | 判据能直接用 `node scripts/…` 运行，不经过 `pnpm run` 或 `pnpm exec` | 换成直跑形态，否则退出码不可信 |
| 4 | 判据此刻跑绿 | 先修判据，现在还不是做有牙实验的时候 |
| 5 | 已选定本次走哪个改坏档：A 手写改坏、B 变异算子、C 回滚真实故障（§六，**默认 A**） | 先选档，再动手；不许边做边换档 |

**不要把改坏档与项目成熟档混用**：这里的 A / B / C 是「怎么改坏」，而 T0 / T1 / T2 是「项目成熟到哪一档」，把 T1 传给 `teeth --tier` 是错的。档 B 的结果不许与档 A 混算（§6.2 第 3 条）。

## 步骤

1. **固定基线。** 记下实现文件的内容哈希与 `assertionId`；`assertionId` 指向 `claim` 的标识，不是某条断言的语法位置（§6.1）。
2. **对齐承诺。** 写下这次改坏应当打掉哪一条 `claim`、`observable` 落在哪个具体值上，并确认实验结论不越出这条判据的 `scope`。
3. **改坏实现。** 按选定的档位动手，一次只留一个改动点；改动点多了以后，失效原因就说不清了。
4. **跑判据。** 只走 `teeth` 这条命令（§八 的 `teeth` 行），把结论交给它的退出码。
5. **定状态。** 从 §6.1 的唯一清单里挑恰好一个结论值写进 `teeth`。清单里有两个值不是可挑的结论：`pending` 一出现就判红，`restore-failed` 是事故并退 2。如果挑不出值，说明这是不认识的状态，按 §6.1 的规则一交退出码 3，不许拿近似值顶上。
6. **还原实现。** 把实现改回去，重算哈希并与第 1 步比对。两者不一致就是 `restore-failed`，退出码为 2，此时停下查仓库状态（§6.2 第 1 条）。
7. **复跑判据。** 还原之后再跑一次判据，要求它通过。如果跑不绿，说明判据本身不稳定，不许标成有牙（§6.2 第 2 条）。
8. **记账。** `killed` 落进「算数」；`survived`、`no-coverage`、`compile-error`、`runtime-error`、`timeout`、`red-wrong-assertion`、`hollow-assertion` 落进「无牙」；没做实验的留空，落进「未做实验」（§3.4.1）。**`ignored` 单列**：它不进分母，也不落进四分里的任何一行，因为它表示「人显式放弃这条判据」；报告必须单独列出被忽略的判据，不许把它混进任何一栏。

## 出口判据

| 编号 | 判什么 | 不过的样子 |
|---|---|---|
| 1 | `teeth` 的退出码只落在 0、1、2、3 四个值里 | 出现别的值 |
| 2 | `teeth` 的落值在 §6.1 唯一清单的 11 个值里 | 落在清单外，而页面仍显示「通过」 |
| 3 | 故意造一次还原失败，结果必须是退 2 | 造了还原失败却退 0 或退 1，说明事故被当成判定 |
| 4 | 复跑返回通过，`teeth` 才允许写 `killed` | 复跑没通过而 `teeth` 仍写 `killed`，应改标为不稳定 |
| 5 | 语法扫描报「疑似空心」时，页面只出提示，`teeth` 不因提示改变 | 语法一命中就把 `teeth` 改成 `hollow-assertion` |
| 6 | 造一条 `teeth=survived` 的判据后跑 `status --html`，它必须计入「无牙」 | 它被计入「算数」 |
| 7 | 本轮只挑一个契约 | 同一轮里静默把两件事都做完 |

**纯技能版没有 `teeth` CLI。** 路由器 [SKILL.md](../SKILL.md) 的 §零 已经写明这套东西没有钩子、没有运行器，所以本卡的执行方式是：读者按步骤 1–8 **代演**这条命令的语义，用 `node scripts/…` 直跑拿真实退出码来定状态，并且自己完成还原核哈希与复跑。退出码语义对应关系是：`killed` 对 0、无牙对 1、还原失败对 2、未知状态对 3。读者必须在记录里如实写「无 CLI，按代演执行」，不许伪造 CLI 输出。

## 三个不可省的落值形状

```text
① teeth 至少写成 {"status": "<§6.1 清单值>", "at": "YYYY-MM-DD", "variant": "A|B|C"}；at 是实验当天，门 2 用它判 90 天有效期。
② 还原失败与复跑不通过是两件事：前者退 2（事故），后者说明判据不稳定。
③ ignored 不落四分、不进分母，报告里单独列。
```

## 业界做法参考

| 参考 | 它做到哪一步 | 本卡的差异与两个代价 |
|---|---|---|
| StrykerJS（B3、B5 首选） | 它逐个注入变异体并单独重跑检查，存活者就是「没牙」的具体位置；`thresholds.break` 让分数低于阈值时退出码为 1 | 本卡一次只改一处，也不设分数门槛。代价是本卡靠人选改坏点、一次只出一条结论；换来的是每条结论都能追到人写的 `claim`，不让算子替人猜意图 |
| StrykerJS 与 PIT 的 `timeout` 口径 | 这两家都把超时计入 detected，PIT 记作 `TIMED_OUT(true)` | 本卡把 `timeout` 单列、不计入有牙。这是本项目的保守选择，不是业界共识（§6.1）。代价是同一批判据里，业界算有牙的若干条本卡算无牙，有牙率会被低估；换来的是不把「判据自己太慢」记成抓到了故障 |
| PIT（B5） | 它把覆盖率与变异分数分开，并用 `mutationThreshold` 当构建门槛 | 本卡不设分数门槛。代价是没有整批趋势信号，判据整体退化只能逐条发现；换来的是不因一条判据翻盘就把整轮判定推翻 |
| Arena-Hard-Auto（J1） | 它用置信区间是否重叠来判断题目是否饱和，饱和就整批换题 | 本卡只判单条判据的这一次改坏，不测整批饱和。代价是整套判据一起饱和时不会被发现，这个量在本项目里估不出来；换来的是单条改坏几分钟内就能出定论 |
