# 门 3 · 有牙

## 入口条件

- 门 2 已过：这条判据已声明 `claim`、`observable`、`scope`（三件套定义在 §6.1 的表；§四 里没有，§6.2 第 4 条只提 claim 与 observable）。缺任何一件，先回 [门 2](./门2-判据.md)。
- 手上有被测实现文件的路径，并能算出它的内容哈希。
- 判据能直接跑：`node scripts/…` 形式，不经 `pnpm run` 或 `pnpm exec`。
- 判据此刻跑绿。跑不绿的话，这一步是修判据，不是有牙实验。
- 已选定本次走哪个**改坏档**（A 手写改坏 / B 变异算子 / C 回滚真实故障，§六，**默认 A**）。**别与项目成熟档 T0 / T1 / T2 混用**——两个「档」不是一回事，把 T1 传给 `teeth --tier` 是错的。档 B 的结果不许与档 A 混算（§6.2 第 3 条）。

## 步骤

1. 固定基线：记下实现文件哈希与 `assertionId`。`assertionId` 指向 `claim` 的标识，不是某条断言的语法位置（§6.1）。
2. 对齐承诺：写下这次改坏应当打掉哪条 `claim`，`observable` 落在哪个具体值上，以及结论不越出 `scope`。
3. 改坏：按选定档位动手，一次只留一个改动点，别让失效原因说不清。
4. 跑判据：只走 `teeth` 这条命令（§八 的 `teeth` 行），把结论交给它的退出码。**纯技能版没有 teeth CLI**（路由器 SKILL.md §零 说过：没有钩子、没有运行器）——本卡的读法是**你按步骤 1–8 代演这条命令的语义**：判据用 `node scripts\…` 直跑拿真实退出码定状态，还原核哈希、复跑都自己做；退出码语义对应写清（killed→0、无牙→1、还原失败→2、未知状态→3），偏离声明如实写「无 CLI，按代演执行」，不许伪造 CLI 输出。
5. 定状态：从 §6.1 唯一清单里挑恰好一个**结论值**写进 `teeth`——注意清单里有 2 个不是可挑的结论：`pending`（出现即判红）与 `restore-failed`（事故，退出码 2）。挑不出来，说明这是不认识的状态，按 §6.1 规则一交退出码 3，不许拿近似值顶上。**落值形状至少 `{"status": "<那个值>", "at": "YYYY-MM-DD", "variant": "A|B|C"}`**；`at` 写实验当天，门 2.5 用它判 90 天有效期，只写 `status` 的按没写全处理。**teeth 落值不改 `frozenHash`、无需重签**——G-09 归一化把 `frozenHash` 与 `teeth` 都排除在哈希输入外（teeth 是实验记录，不是判据承诺）；改判据承诺的字段才要重算重签。
6. 还原：改回去，重算哈希并与第 1 步比对。不一致即 `restore-failed`，退出码 2，停下查仓库状态（§6.2 第 1 条）。
7. 复跑：还原后再跑一次判据，要求通过。跑不绿说明判据不稳定，不许标有牙（§6.2 第 2 条）。
8. 记账：`killed` 落「算数」；`survived`、`no-coverage`、`compile-error`、`runtime-error`、`timeout`、`red-wrong-assertion`、`hollow-assertion` 落「无牙」；没做实验的留空落「未做实验」（§3.4.1）。**`ignored` 单列、不进分母、不落四分里任何一行**——它既不是「无牙」也不是「未做实验」，是「人显式放弃这条判据」（§3.4.1 末两条规则 + §6.1）；报告必须单独列出被忽略的判据，不许混进任何一栏。

## 出口判据

1. 跑 `teeth <契约标识> <判据标识> --tier <A|B|C>`（§八 的实测形态；`--contract`、`--criterion` 这两个开关规格里没有，别自己发明），看退出码：只能是 0、1、2、3 之一；出现别的值算失败。
2. 查 `teeth` 的落值：必须在 §6.1 唯一清单的 11 个值里；落在清单外而页面显示「通过」算失败，正确结果是退出码 3 与「无法判断」。
3. 故意造一次还原失败（还原后多改一个字符）再跑：退出码必须是 2；返回 0 或 1 算失败——这是事故，不是判定结果（§6.2 第 1 条）。没有 CLI 跑不了这一条时，按步骤 4 的代演口径手工判一次并如实记「代演」；判不了就写「无法执行」，不许省略后装作过了。
4. 第 7 步复跑返回不是 `passed`，而 `teeth` 仍写着 `killed`，算失败；正确做法是把这条判据标成不稳定。
5. 拿一条语法扫描报「疑似空心」的判据跑一次：页面只出提示，`teeth` 不因提示改变；语法命中就把 `teeth` 改成 `hollow-assertion` 算失败（§6.1、§6.2 第 4 条）。
6. 造一条 `teeth=survived` 的判据后跑 `status --html`：它必须计入「无牙」；计入「算数」算失败（§3.4.1）。
7. **本轮只挑一个契约。** 任务让你做两件事时，只做一件，另一件写进缺口清单并注明「任务与 §9.1 第 3 步冲突」——静默把两件都做完，本条判不通过。

## 业界做法参考

| 参考 | 它做到哪一步 | 本卡的差异与两个代价 |
|---|---|---|
| StrykerJS（B3、B5 首选） | 逐个注入变异体、单独重跑检查，存活者即「没牙」的具体位置；`thresholds.break` 让分数低于阈值时退出 1 | 本卡一次只改一处、不设分数门槛。代价：Stryker 能整仓自动跑一遍，本卡靠人选改坏点、一次只出一条结论；换来：每条结论都能追到人写的 `claim`，不让算子替人猜意图 |
| StrykerJS / PIT 的 `timeout` 口径 | 两家都把超时计入 detected（PIT 记 `TIMED_OUT(true)`） | 本卡单列 `timeout`、不计入有牙，是本项目的保守选择，不是业界共识（§6.1）。代价：同一批判据里，业界算有牙的若干条本卡算无牙，有牙率会被低估；换来：不把「判据自己太慢」记成抓到了故障 |
| PIT（B5） | 把覆盖率与变异分数分开，并用 `mutationThreshold` 当构建门槛 | 本卡不设分数门槛。代价：没有整批趋势信号，判据整体退化只能逐条发现；换来：不因一条判据翻盘就把整轮判定推翻 |
| Arena-Hard-Auto（J1） | 用置信区间是否重叠判断题集已饱和，饱和就整批换题 | 本卡只判单条判据这一次改坏，不测整批饱和。代价：整套判据一起饱和时不会被发现，这个量本项目估不出来（unquantified）；换来：单条改坏几分钟内出定论 |
