# 状态与功能树

**这张卡回答**：一轮结束时，怎么把「哪些功能做到哪、这一轮到底算不算过」变成一段别人能复核的输出。状态词、总账格式、判定表都在规格里，本卡只给三样：怎么操作、按什么顺序、什么算过。

## 入口条件

- 这一轮的判据已经跑完，证据按 [门4-证据](./门4-证据.md) 落成三件套。**没有证据的义务不出状态**：三件套断任何一环、或材料读不出来，判 `无法判断`（§2.6、§四）；**只有「还没跑过」才是 `未验证`**——两者别混，一个是事故态，一个是没开始。
- `contract.json` 与 `functions/*.json` 都在（字段见 [模板-functions.json](./模板-functions.json.md)），分类器读 `tools/classification.json`（私有仓）——它是 §3.4.1 判定表的机器可读权威。
- 本卡只出「本轮 N 项」这一整段，不改判据、不改 `teeth`、不改 `pendingRecheck`。那三样属于前面的卡，在出总账这一步动手就是拿结果改条件。

## 步骤

1. **先归四数，再归六栏。** 对每条义务取 `run`、`pendingRecheck`、`teeth` 三个输入，按 §3.4.1 的判定表**从上往下逐行匹配，第一条命中即止**。不要按「看上去更合理」挑行——这个顺序本身就是规则。先看 `run`：**`run ≠ pass` 的不进这四行**，按结果走「未通过」或「无法判断」（§3.4.1 表末第二条）。只有 `run = pass` 才逐行匹配；**`run = pass` 却四行都不命中**才是「规格没定义这个组合」，判红、退出码 3。**两个例外先拎出来**：`teeth = ignored` 不落四栏也不进分母，页面单列即可；`pending` 这种规格明说不允许出现的值出现即判红。
2. **两个等式都要成立**：`A1 + A2 + A3 + A4 = A`，`A + C + D + E + F + G = N`（§3.4，INV-16）。任一处不成立就停下，**不许改 N 或改子数去配平**。总账文本逐字照 §3.4 抄，模板见 [模板-总账](./模板-总账.md)。
3. **算功能层两个计数**（§3.3.1）：孤儿功能进缺口清单；**孤儿契约逐条列清单、标「未登记功能」，不许自动归到任何功能上**——该挂哪个功能是人的业务判断，机器只负责指出它没人认领。
4. **出树**：`status --tree`，默认折叠到功能层。节点符号只用 §17.2 那五个，排序按 §17.3 最差的在上，形状照 §17.4，**不许折算成百分比**。
5. **只画人说过的顺序**：`status --flow` 里 `source` 为空的功能不进图（§17.1.2 的三种情形分别处置），顺序画反机器判不出来，交给人在图上说。

## 业界做法参考

| 参考 | 它做到哪一步 | 与本卡的差异 |
|---|---|---|
| E1 claude-mem | 挂在工具事件上，把「读了什么、改了什么」自动压成记忆，下次开工自动注入摘要 | 它记的是文件动作，不判「算不算通过」，也不校验旧记忆与代码是否冲突。本卡反过来：状态必须由一次真实运行派生。代价对照：它每轮零额外动作，但输出里没有「通过 / 未通过」这一栏；本卡每轮多三份证据文件、多一次判定表匹配，换来状态可复核 |
| D2 beads | 把活拆成带依赖边的图，`bd ready` 查「下一步做什么」，进度靠 claim / close 维护 | 它答「下一步做哪件」，本卡答「这一轮做到哪、哪些功能没挂契约」，不做任务排序。代价对照：它靠 agent 主动 claim / close 两步维持进度，一旦漏写就静默失真；本卡靠证据落盘与两个等式自校验，代价是每轮固定多一遍分类与相加 |
| E1 备选 Spec Kit · converge | 反复 implement 与 converge，直到报告 `Converged`，拿它比文档进度与代码 | 它只做漂移检测这一段，本卡把漂移落成两个可数的缺口（孤儿功能、孤儿契约）并强制列清单，而不是给一个收敛结论 |

## 出口判据

1. 跑 `status --tree`，把六栏六个数字相加、把四子数相加：`A + C + D + E + F + G ≠ N` 或 `A1 + A2 + A3 + A4 ≠ A` 即失败。
2. 把每条义务的三个输入代进 §3.4.1：出现一条同时命中两行，或一条 `run = pass` 且 `teeth ≠ ignored` 却一行都不命中，即失败（`ignored` 本来就不命中，不算失败）（互斥、穷尽各查一次）。
3. 数孤儿契约：清单条数 ≠ 「有契约但没被任何 `functions[].contracts` 引用、**且 `retired` 为空**」的契约数（退役契约不进任何计数，§2.3），即失败；清单里出现被归入某功能的条目，即失败。
4. 扫树上每个节点的符号：不在 §17.2 的五个符号之内，或输出里出现「%」，即失败。**例外**：`⚠ 未登记功能` 这类提示节点不是状态符号，§17.4 的树本来就该有它，别把它判红。
5. 从上往下读树的次序（§17.3 完整次序）：`✗ 未通过 → ◐ 无牙 → ○ 未验证 → ⬤ 通过 → ∅ 过期`。任何一档排错位置即失败——**「过期」排在通过之后也是规定的一部分，别只查前四档**。
6. 扫 `status --flow` 每个框：`contracts` 为空或 `source` 为空却仍在图里，即失败（§17.1.2、§17.5）。
