# 交接包

## 入口条件

- 本轮已到阶段 6。阶段 1–5 不做交接，交接这一阶段不可跳过（§九）。
- 状态算得出来：先跑一次 `handover`，退出码 0 才有料可交。退出码 3 表示无法判断、材料不足，去补材料，不许手填（§八）。
- 项目已进入阶段 6 时，门 0.4 生效：`HANDOVER.md` 六节齐，且含一条非空的接收方验收记录；阶段早于 6 时这条不查（§15.0）。
- 手边有 `INTENT.md`、`CONSTRAINTS.md`，以及当场 `status` 出的总账（§三）。

## 步骤

1. **生成，不手写。** 跑 `handover`（§八），拿到六节：当前状态、下一个该做的、未定事项、最近三条决策、已知缺口、怎么跑起来（实例见 [03-走查.md](../../设计/03-走查.md) 第 21 天）。节名与节序照输出，不加节、不改名。
2. **第一节贴状态。** 六栏总账与通过四分逐格照命令输出抄（§三）；六栏相加要等于总项数，加不起来是算错，不凑。不许凭会话记忆报数。
3. **第二节写下一件事。** 从 `gaps` 里只挑一条，写清是哪条契约、哪条判据；判据带 `claim` / `observable` / `scope` 三项（定义在 §6.1），缺一项接收方跑不起来。挑的不在缺口前 3 位就写 `skipReason`（§15.0）。
4. **无牙与未做实验的项要带证据线索**：附最近一次 `teeth` 的变异体状态（§六、§八）；**没做过实验的写「未做实验」（A3，状态仍是「通过」），不许写成「无法判断」**——那是材料读不出来的事故态（§3.4.1）；留空按没写算。
5. **第六节写怎么跑。** 三条命令原样可粘：冒烟、该契约判据、`status`；写子进程直跑的形态，不写经 `pnpm` 的（[SKILL.md](../SKILL.md) 第五节）。当前档位（T0 / T1 / T2）也写在这节（§九）。
6. **交给接收方跑一遍。** 找一个没参与的人或全新会话，对一个真实使用场景跑，写进**第六节末尾的固定子块** `### 接收方验收记录`，四要素缺一即空：谁跑的、跑的命令原文、看到的输出、卡住的格（G-05）；只复述文档不算（§九 阶段 6 ②）。
7. **再做十分钟实测。** 题本固定四问（做到哪、下一步、怎么验证、这份文档不覆盖什么），逐问作答并计时；结果与接收方验收记录一起留在仓库文件里，下一轮开工只认文件（**四问题本见 §九 阶段 6 与 `06-验证方案.md` V3；§15.0 只规定六节与验收记录，没有题本**）。

## 出口判据

1. `handover` 退出码为 0。出现 3 判失败：状态算不出来该去补材料，不是手写补数（§八）。
2. 六节齐、节名与 `handover` 输出一致，接收方验收记录非空。缺节或字段为空判失败（判法见 §15.0 0.4）。
3. 十分钟实测：3 个没参与过的会话，只给 `HANDOVER.md`，计时答四问——现在做到哪、下一步做什么、怎么验证、这份文档不覆盖什么。有 1 个没四问全对，或中位耗时超过 10 分钟，判失败（口径见 [06-验证方案.md](../../设计/06-验证方案.md)）。
4. 题本不许改：换成三问、五问，或拿「看懂了吗」代替逐问作答，判失败；第四问答成「都覆盖了」也判失败。
5. 总账可复现：把第一节六栏总账与当场 `status` 输出逐格比，一格不同判失败（§三）。
6. 命令可粘：照第六节原样粘进新会话，有一条要改路径、要补参数或跑不起来，判失败。

## 业界做法参考

| 参考 | 它做到哪一步 | 本卡与它的差异 |
|---|---|---|
| GitHub Spec Kit（E5 首选） | 需求、取舍、验收结论固化成版本库里可 diff 的文档，最后一步的 handoff summary 直接交下一阶段 | 它交的是一份摘要；本卡要六节加固定四问，摘要不算交出去 |
| Cline Memory Bank（E5 第 2 条） | 固定结构的 `memory-bank/` 承载当前焦点与进度，会话开头读、有变化回写 | 它靠 agent 自觉回写；本卡状态由命令现算，写错会在总账复现那一步被抓到 |
| beads（H5 首选） | 现状放进 Dolt 依赖图，agent 的 claim / close 就是人看到的同一份状态 | 它要装 CLI 并靠 push / pull 同步；本卡不引外部状态库 |

**两处差异各付什么代价**（口径见 [adr/015](../../设计/adr/015-说现成做法不适用必须给两个代价.md)）：交接耗时——Spec Kit 写一份摘要按十分钟算，本卡要六节加 3 个会话实测，按 [07-结论.md](../../设计/07-结论.md) 单次 1 小时的估法算 **3 小时**，多 2 小时 50 分——**别按一次会话估**；外部依赖——beads 用单一状态源换掉两边对齐，但要装 CLI 加同步，本卡 0 个外部依赖，代价是每次交接都得重算一次状态，算不出来（退出码 3）时交接根本做不下去。
