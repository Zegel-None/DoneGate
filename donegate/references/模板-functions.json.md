# 模板 · `functions/<id>.json`

`functions/<id>.json` 是流程图上一个框的唯一载体：一条成功条件加一组机器可验的锚点。字段与必填只看 [§2.3.1](../../设计/02-规格.md)，本卡只写怎么落笔。

## 入口条件

- 意图已定稿，「什么算成功」里能整句引用原文（[§2.1](../../设计/02-规格.md)）；找不到先补意图。
- 人说过这个框（`source` 必填，逐字摘原话）。**`after` 是选填**：人没说顺序就先只建框、不建连线，别因为「没听到先后」就不建框。
- `functions/` 下没有同名 `id` 的文件；有就改那一份。

## 步骤

1. 定 `id` 与 `title`：`id` 把业务名转成小写连字符（如 `booking-crossmidnight`），`title` 一句话写给人看。两样由 Agent 起草，人要能指着说「不对」。
2. 摘 `successCriterion`：从意图的「什么算成功」整句复制，不改写、不拼接两句（§2.3.1）。
3. 逐字摘 `source`：把人说这个框的那段话原样放进去，语气词、标点、语序都留；顺序句与功能句一起摘，不切分、不润色、不总结；摘完并排倒着读一遍。
4. 推 `after`：从人的顺序词（「然后」「之后」「先…再…」）推出上游框的 `id`，只写 `id` 不写 `title`；人没说顺序就留空数组等他说，不按业务逻辑猜（§2.3.1：由 Agent 生成，人不直接编辑）。
5. 起草 `contracts`：写下这个框挂哪些契约，再把草案交人确认；一个都不挂写成空数组，按 §2.3.1 就是声明了没做。
6. 让人看图说「不对」：他指哪条连线错，只改这一个文件，别人的框不动。文件里不写状态。
7. 落盘后跑一次 `status --flow`，把结果贴回给人；报红按出口判据逐条查，不改判据去迁就数据。示例照下面改。

```json
{
  "id": "booking-crossmidnight",
  "title": "跨零点的预约按开始日算一单",
  "successCriterion": "客人能在跨零点的时段订到一间房",
  "contracts": ["booking-create"],
  "after": ["booking-shift-pick"],
  "source": "晚上十一点的预约跨到第二天凌晨一点，现在给我拆成两单了；这个框排在下班时间选择后面，得按开始那天算一张单。",
  "note": "以前按自然日切单，跨零点就成了两单。"
}
```

字段与示例逐栏对应：

| 字段 | 落笔动作 | 出处 |
|---|---|---|
| `id` / `title` | 业务名转小写连字符、与文件名一致；一句话给人看 | §2.3.1 |
| `successCriterion` | 意图原文整句复制，标点不动 | §2.1、§2.3.1 |
| `contracts` | 至少一个契约标识；起草后交人确认 | §2.3.1 |
| `after` | 只写上游框的 `id`；Agent 从人的自然语言生成，人不直接编辑 | §2.3.1 |
| `source` | 人的原话逐字，含语气词与标点；空即红 | §一 INV-18 |
| `note` | 一句为什么存在；可省 | §2.3.1 |

## 出口判据

1. 用任意 JSON 解析器读一遍：解析报错，或缺 `id` / `title` / `successCriterion` / `contracts` / `source` 任一栏，即判不过（§2.3.1）。
2. 跑 `status --flow`：退出码必须是 0，且输出里有这个 `id`。§八 给 `status` 只定义了一个失败码：**3（有契约读不出来）**；1 与 2 不是 `status` 的失败码，出现了说明跑错了命令或包装层动了手脚，按 [§八](../../设计/02-规格.md) 记事故。
3. 把 `source` 与人的原话并排逐字比：差一个字、少一个标点、删一个语气词，即判不过；`source` 为空时 `status --flow` 必须拒绝渲染并报红（§一 INV-18）。写成「基于分析」的，过不了这一关。
4. 把 `successCriterion` 拿到意图文件里整句搜：搜不到即判不过；用「意思一样」放行同样判不过（§2.3.1）。
5. 数 `contracts`：空数组、或有一项找不到同名契约 `id`，**这是「孤儿功能（声明了没做）」**——按 §3.3.1 进缺口清单，**不是本卡判不过**；本卡只负责把这一条如实报出来。
6. 逐个数 `after` 里的 `id`：有一个在 `functions/` 下找不到同名文件即判不过；只判连线指得到，不判顺序对不对。

## 业界做法参考

| 参考条目 | 它做到哪一步 | 本卡与它的差异 |
|---|---|---|
| E1 首选 · claude-mem | 在会话事件上挂钩子，把工具调用压成观察记录存本地库，下次开工自动注入摘要，人不写笔记 | 本卡不存过程记忆：每个框只留逐字原话，压缩后的转述不算数 |
| E1 备选 · beads | 把进度做成带依赖边的任务图，查当前可做与在做 | 本卡的连线只有横向顺序一种，且顺序由人说出来；不建可查询的任务图 |
| E1 备选 · OpenSpec | 每个变更一份逐条可勾的清单，勾完才收尾、归档 | 本卡的清单就是功能框本身，完成度由契约与判据算，人不逐条勾 |

**差异与两个代价**，单位都取「一条功能」：走 claude-mem 式自动记忆，一条功能付 0 次人工摘录，但 `source` 成了压缩转述，出口判据第 3 条每次必红，另加一个本地 worker 与一份库；本卡一条功能付 1 次逐字比对，另加「人没说顺序就留空等」的等待，换来第 3 条判据能判真假。口径见 [ADR-015](../../设计/adr/015-说现成做法不适用必须给两个代价.md)。
