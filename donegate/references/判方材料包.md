# 判方材料包

一个契约一次打包：给什么、不给什么、每样在哪。判方只拿原料自己算，不拿写方算好的结论。

## 入口条件

1. 这个契约的判据已冻结、证据三件套齐（§2.6）。缺一份就先补证据，别用说明文字填空。
2. 这一轮只动过这一个契约 `scope` 内的代码；跨契约的改动不进这一包。
3. 判方是另一个模型（§7.4）。同一个模型来判，包做得再干净也白做。
4. 包的唯一用途：判方只凭它，对 §七 五项各答 `pass` / `fail` / `unknown`（§7.1）。答不出的项就是包的缺口。

## 步骤

1. **建目录**：一个契约一包，目录名用契约 `id`；包内只放文件。
2. **逐字放判据原文**：从冻结后的契约取，含 `id`、`kind`、`command`、`expect`、`frozenHash`、`signedBy`、`required`、`inputClasses`、`servesSuccessCriterion`、`teeth`，以及三件套 `claim` / `observable` / `scope`（§2.4 必填项加 §6.1 三件套；**少给 `signedBy` 与三件套，判方判不了 V2 与 V5**）。不摘要、不改写、不合并——差一个字就算没给。
3. **放 `base..head`**：两个版本号加它们之间的 diff；diff 要能让判方定位到行，别只写「改了哪几个文件」。
4. **放运行输出与退出码**：三份证据文件原样复制（§2.6）。退出码按 §八 的四值原样给，不要换算成「成功 / 失败」，不要贴经包装层跑出来的结果。
5. **放 `scope`、`why` 与完成声称的原文**：前两样原文件复制、逐字（不加「我为什么这么划」的补充段）；**第三样是写方「这次做完了什么」的原话**，INV-14 规定复核包只许含五类且五类必须齐，缺了它判方判不了 V5（无越界）。
6. **删掉不给的**：写方的计划、对话历史、思路草稿、其他契约的任何内容（判据、`scope`、决策记录）。**INV-14 是白名单不是黑名单：复核包只许含五类，出现第六类即红。** 所以「§7.4 的表没列它」不等于「可以给」——写方自己算的总账、通过四分、缺口清单都属第六类，**一律不进包**。上一轮这里写成「想不给就写进决策记录」，那是错的：决策记录是写给未来的，不是给你开的口子。
7. **例外单独附**：本轮按 §7.2 改过判据的，把决策记录附进来；缺了判方只能答 `fail`。
8. **交接前自检**：交给一个没有本轮上下文的判方，要它先列「缺哪些文件」再作答；缺文件的项按 §7.3 的落地检查写具体文件名，写不出文件名的项不算缺口。
9. **锁包**：记下包的内容哈希；包内改动一次就重出一包，不覆写旧包。

## 出口判据

1. **五类齐（INV-14 的白名单：少一类即红，多出第六类也红）**：判据原文（含 `expect` 与 `assertionId`）、`base..head`、运行输出与退出码、契约的 `scope` 与 `why`、完成声称的原文，五类都要能逐一点出。
2. **清单闭合**：对包目录跑一次文件清单（如 `Get-ChildItem -Recurse -File`），与**包内 `MANIFEST.txt`** 逐条对得上——步骤 1 建目录时就要生成它，逐行一个相对路径加哈希，**只列其余文件、不列它自己**（自己列不了自己的哈希）；出现清单外文件、或多出/缺少条目即失败。
3. **判据原文没走样**：**逐条**与冻结契约比哈希（不是随机抽一条——抽一条覆盖不到其余，同一个包重跑会时过时不过）；任一条不一致即失败。
4. **无叙述材料**：在**判据原文以外**的部分检索「计划」「思路」「草稿」与第一人称推理句式；命中一处即失败（判据命令里可能合法出现这些词，不能连它一起判）。
5. **退三演练**：抽掉 `scope` 那一份后重跑判方作答，V1 必须答 `unknown` 并写明缺哪个文件；答 `pass` 或答不出文件名即失败（§7.3）。
6. **退出码没被吞**：抽一条判据重跑，报告里的退出码与重跑直读的一致，且在四值之内；输出报错而退出码为 `0`，或命令经过包装层，即失败。
7. **无越界材料**：包内出现其他契约 `id` 的命中，即失败。

## 业界做法参考

| 参考 | 它做到哪一步 | 本卡与它的差异 |
|---|---|---|
| F2 · superpowers `requesting-code-review` | 派发审阅时只传改动说明、需求与两个 SHA，明令不带作者会话历史 | 方向相同；本卡把「不给」落成可检索、可 diff 的四类清单，不只写成对写方的要求 |
| F2 · superpowers `code-reviewer` | 审阅者必须列出「考虑过但不归本次审阅」的行为 | 本卡挪到材料侧：缺口必须写缺哪个文件（§7.3）。代价是写方每次发包多一道核对，换来 `unknown` 可复核；现成做法把这笔时间算在审阅者身上 |
| F1 · Review Board | 逐文件标记 Reviewed，覆盖状态可审计 | 差异明显。两个代价：现成做法要养一台评审服务与长期标记状态（按部署维护工时算），本卡只在归档时核对一次目录（按每次发包核对次数算）；但本卡没有跨包的持续覆盖状态 |
| F1 · PR-Agent | 把大 diff 压成逐文件摘要再喂给审阅者 | 本卡拒绝压缩判据原文。两个代价：现成做法按压缩比减少单次读入量，本卡按原文全量给、判方读得多；换来判据字面可逐字核对 |
