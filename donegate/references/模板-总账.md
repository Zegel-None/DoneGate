# 模板-总账

**这张卡回答**：每轮收尾贴的一行状态统计（即「总账」）怎么贴、按什么顺序算、什么算贴错。格式与判定规则在 [02-规格](../../设计/02-规格.md) §3.4 与 §3.4.1，本卡只写怎么操作、按什么顺序、什么算过。

## 入口条件

- 本轮判据已经跑完，每条义务的 `run`、`teeth`、`pendingRecheck` 都已落进台账（取证见 [模板-证据记录](./模板-证据记录.md)；取值以 §3.4.1 与 §六 为准）。
- 每个数都能指到一条命令输出或一份证据记录；指不到的项停在 `未验证`，不要先猜数再补证据。
- 这一轮不改判据、`teeth`、`pendingRecheck`——贴总账时动手等于拿结果改条件。

## 步骤

1. **先定 N**：N 是本轮**进分母**的义务数。分母指计入统计的义务项；标记无需改坏实验的项（`teeth = ignored`，§3.4.1）不进分母。N 只能数出来，不能从六栏倒推。
2. **再归六栏**：每条义务只落进一栏，六栏名称与顺序固定（§3.4）。六栏为通过、未通过、未验证、过期、无法判断与不稳定。`不稳定` 是第六栏、占分母：绿红绿就记这里，别塞进通过或未通过。六栏相加等于分母 N；加不起来就重算，不许改 N 配平。
3. **再拆通过四分**：通过四分指通过项拆成的四个子数。对每条 `run = pass` 的义务取 `pendingRecheck` 与 `teeth` 两个输入，按 §3.4.1 判定表**从上往下四行依次套，第一条命中即止**。四个子数：算数（做过有牙实验、改坏时能红、也不用重验的通过，即 A1）、无牙（跑绿但改坏实验说明判据没牙，即 A2）、未做实验（跑绿但从没做过改坏实验，即 A3）、待重验（跑绿但上游材料变了要先重跑，即 A4）。不要先分「有牙」再回头补「待重验」——顺序反了会把待重验算成算数，而四个子数加总仍对得上。
4. **逐字贴**下面这段，只换数字，冒号、顿号、空格、栏名顺序一律不动：

```text
本轮 N 项：通过 A、未通过 C、未验证 D、过期 E、无法判断 F、不稳定 G
其中通过里：算数 A1、无牙 A2、未做实验 A3、待重验 A4
```

5. **用四个算例照一遍本行**，重点比对第二、第三与第四个：它们都能骗过一眼（第四个连加总都能骗过）。

### 四个算例

**算例一 · 正常**（两个等式都成立）：

```text
本轮 8 项：通过 5、未通过 1、未验证 1、过期 0、无法判断 0、不稳定 1
其中通过里：算数 2、无牙 1、未做实验 1、待重验 1
```

六栏相加为 8、四个子数相加为 5，与 N 和「通过」一致。

**算例二 · 六栏加不起来**：

```text
本轮 7 项：通过 5、未通过 1、未验证 1、过期 1、无法判断 0、不稳定 0
其中通过里：算数 2、无牙 1、未做实验 1、待重验 1
```

六栏相加是 8，与 7 不等，这一行作废：回去找落错栏那条，**不许把 N 改成 8 配平**。

**算例三 · 通过里四个子数填错**（加总对、归类错）：

```text
本轮 6 项：通过 4、未通过 2、未验证 0、过期 0、无法判断 0、不稳定 0
其中通过里：算数 3、无牙 1、未做实验 0、待重验 0
```

四个子数相加是 4，与「通过 4」相等，两个等式都过，错在里面：一条 `run = pass`、`pendingRecheck = true`、`teeth = killed` 的义务被记成算数，按 §3.4.1 该进待重验。加总抓不到，顺序复判才抓得到。

**算例四 · 本轮一个判据都没做过有牙实验**（T1a 阶段的常态，§15.6 说第 1 个月这些门还没生效）：

```text
本轮 3 项：通过 3、未通过 0、未验证 0、过期 0、无法判断 0、不稳定 0
其中通过里：算数 0、无牙 0、未做实验 3、待重验 0
```

**这是最容易错的一格，也是本卡唯一一个「三条都跑绿、却一条都不算数」的形态。** 三条都 `run = pass` 但 `teeth` 都没有字段（`undefined`），按 §3.4.1 命中**第 4 行 A3**，不是第 2 行 A1。常见错法两种，都骗得过加总：把「跑绿」当「算数」写 A1=3（读起来更漂亮）；或 A2 与 A3 都填 3（违反出口 5「不重叠」）。**判据跑绿只说明「通过」这一栏，不说明四分子数里它算数**——算数只数 `teeth = killed`。

## 业界做法参考

| 参考 | 它做到哪一步 | 与本卡的差异 |
|---|---|---|
| D2 首选 Beads（bd） | 把活拆成带阻塞依赖的节点图存进 `.beads/`，`bd ready` 一条命令给出「无阻塞、可认领」的项 | 它答「下一步做哪条」，本卡只答「这一轮的数怎么算」；现状在它那里是上下文外的库，本卡里是两行文字 |
| Task Master | 把 PRD 解析成带依赖的清单，`next_task` 给下一个任务，做完写回状态 | 它用清单状态承载进度；本卡不产生新状态，只把已有计数排成固定两行 |
| Spec Kit 的 tasks.md | 把计划落成按阶段与依赖排序的任务清单，实现只按清单执行 | 它管「做哪些」，不管「算不算过」；本卡分母只含本轮跑过的义务 |

**两个代价**：问一次「现状是什么」，Beads 是 1 次命令查询、0 次人工加法；本卡 1 次人工加总（六个数加四个数，须两遍），结果机器读不了。反向：Beads 要一份 Dolt 库加一个 CLI，对单人试点是长期依赖；本卡零依赖，代价是每轮多一遍手工核算。

## 出口判据

1. **逐字比对**：把贴出的两行与步骤 4 的模板对一遍，除数字外任一字符不同（标点、空格、栏名顺序）即失败。
2. **六栏守恒**：六个数相加与 N 比对，不等即失败（§3.4 的 INV-16）。
3. **四分守恒**：`A1 + A2 + A3 + A4` 与「通过」比对，不等即失败。
4. **顺序复判**：把每条 `run = pass` 的义务按 §3.4.1 从上往下重套并记下行号；出现零命中，或行号与步骤 2、3 的归类不同，即失败——加总抓错数，这条抓错栏。**例外**：`teeth = ignored` 按 §3.4.1 本来就不命中四行、也不进分母，它零命中是对的，别判红。
5. **不重叠**：同一条义务在六栏里出现两次，或同时进两个子数，即失败。
6. **数有出处**：任一个数指不回命令输出或证据记录，即失败。
