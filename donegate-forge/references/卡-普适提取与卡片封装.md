# 卡 · 普适提取与卡片封装

**它回答的问题**：面对形态各异的 GitHub 开源项目——哪怕它自带庞大 Web UI、是常驻服务、只生成文件不做检查、甚至是纯规则/技能文档——怎么不削足适履地把我们需要的核心能力提取出来，封装成完结门画布上可连线、可开关、可验真的模块化卡片与轻量预置工作流？

## 入口条件

- 手头有一个或多个候选开源项目，准备接入完结门或编排进某条工作流。
- 明确「守底线、放形态、轻打包」总则：**只锁死防撒谎底线**（只交客观事实与产物哈希、禁输出状态评语、严守 `0/2/3` 退出码），**绝不锁死工具形态**（不强求本地 CLI 二进制、不限语言、不限阶段数 `1–20`），且**绝不把第三方开源项目源码/体积包捆绑进 Git 仓库**。

## 步骤

1. **按 P1–P4 四条覆盖准则定并存关系与边界。**
   - **P1 先看覆盖再谈数量**：若多个项目的**数据源、作用对象、语言生态、分析精度**不同（例如锁文件漏洞、容器镜像层、SBOM 交叉比对、调用图可达性），它们是互补的**覆盖族**，必须并存并在下游接一张归并卡去重；只有四维高度重合的真重复才二选一。
   - **P2 跨阶段底座复用**：多阶段共用的底座工具只建一份适配器与卡片模板，各阶段靠不同输入端口或参数复用。
   - **P3 真值源冲突不强扭**：若两款工具真值源相反（如版本化迁移脚本 vs 声明式对账），必须指定唯一主真值，另一方只做只读校验。
   - **P4 必填「不覆盖什么」**：每张卡必须在 `blindSpots` 写清它不管什么；写不出边界说明定位不清，不准入网。

2. **对号入座「六类普适形态（`archetype`）」，选对提取通道。**
   不要把所有项目都硬塞进「跑命令行数报错」的窄框子里，按它真实产出的东西选通道：

   | 普适形态 `archetype` | 典型项目举例 | 真实产出物 | 提取方法与底座 `mode` | 画布端口映射（输入 → 输出） |
   |---|---|---|---|---|
   | `scanner` 诊断探针 | Linter、SAST/DAST、Fuzz、压测、变异测试 | 违例计数、定位坐标、性能/覆盖指标 | `binary`：跑无头 JSON/SARIF 输出，提炼纯数值进 `observation.json` | `ARTIFACT/SPEC` → `SIGNAL` + `TEXT` |
   | `generator` 工件生成 | 规格脚手架、OpenAPI 生成、迁移、SBOM、令牌编译、文档站 | 新落盘的代码、SQL、SBOM、配置或构建包 | `binary`：执行生成命令，用 `extraArtifacts[]` 锁死生成物哈希供下游消费 | `SPEC/TEXT` → `ARTIFACT` + `SIGNAL` |
   | `ui-extract` 带 UI 去壳提取 | 组件工作台、原型工具、测试报告站、监控面板、可视化编辑器 | 界面背后的数据内核：组件清单、设计令牌、统计 JSON、静态快照 | **去壳取核三选一**（见第 3 步），绝不在卡片内套娃对方整套前端 | `SPEC/ARTIFACT` → `ARTIFACT/TEXT` |
   | `runtime-service` 运行时与状态 | 容器真库、Mock 替身、有限状态机、持久执行、GitOps、混沌演练 | 正反向演练结果、健康快照、步骤检查点、合法枚举状态 | 提炼为一次性探针、回放脚本或枚举状态快照核对，不在门禁内死等常驻守护进程 | `FLOW/ARTIFACT` → `SIGNAL` + `TEXT` |
   | `knowledge-skill` 知识与技能包 | 设计系统 Usage 指南、Agent 技能集、交互决策表、工程准则库 | 无二进制！产出子代理约束提示词、控件决策表或核查清单 | `mode: 'knowledge'`：免二进制探测，锁定规则文档与版本指纹，向子代理输出提示约束 | `SPEC/ANY` → `PROMPT` + `SPEC` |
   | `aggregator` 覆盖族归并 | 多源漏洞按 `(包名,版本,CVE)` 去重、快慢扫描分层汇总、PR 回贴 | 吃上游多张卡的报告，去重并按可达性排定修复优先级 | `mode: 'artifact'`：免外部二进制，直接读取上游多个观测产物合并落盘 | 多路 `ARTIFACT/TEXT` → `ARTIFACT` + `SIGNAL` |

3. **遇到「自带重 UI 或复杂一体机项目」时，严守「去壳取核」三层剥离法。**
   像组件沙盒、设计平台、报告中心乃至带独立 Web 界面的工程工具，接入完结门时**不抄代码、不改上游、不把对方整套网页嵌进画布节点**，按优先级只抽三样东西之一：
   - **第一优先 · 抽无头导出层（Headless CLI / Build Stats）**：调用其静态导出或构建统计命令（如输出令牌 JSON、组件索引、静态报告摘要），拿到确定性文件即收手。
   - **第二优先 · 抽数据接口层（HTTP / OpenAPI / State JSON）**：若对方作为本地或远端服务运行，适配器只请求其只读 API 抓取结构化快照落盘，并在卡片 `upstream.uiExternalUrl` 填上原生面板地址，供人按需点击新标签页查看。
   - **第三优先 · 抽磁盘工件层（Artifact Snapshot）**：若对方纯靠界面交互落盘工程文件，适配器走 `mode: 'artifact'` 只校验并哈希其产出的工程文件结构。

4. **在 `bricks/<tool>/capabilities.json` 声明模块化卡片外观、端口与按需安装元数据（`install`）。**

5. **按「类 ComfyUI 轻量预置 + 一键补齐依赖」原则落盘 `workflows/<id>.workflow.json`。**
   预置或新增工作流时，**仓库内只提交轻量的 `<id>.workflow.json` 与薄适配器，绝不打包外部 GitHub 项目本身**。在顶层 `deps[]`（或复用的 `bricks/<tool>/capabilities.json` `install`）写明外部依赖：
   - **缺依赖自动禁跑**：只要非跳过节点所需的外部项目或运行环境未就位，`preflightWorkflowPack` 与前端「试跑工作流」均按类 ComfyUI 规则直接阻断（退 `3`），并在左栏工作流旁显示琥珀色 `补齐(N)` 按钮。

## 出口判据

1. 明确写出该项目的 `archetype`（六类普适形态之一或自定义标识）及 P4 边界 `blindSpots[]`（「它不覆盖什么」非空）。
2. 若上游项目自带 UI 或常驻服务，已按「去壳取核」选定无头导出、API 快照或静态产物通道，未在卡片或适配器中硬塞前端界面代码或阻塞守护进程。
3. `bricks/<tool>/capabilities.json` 含合法 `card.inputs[]` 与 `card.outputs[]`（端口 `type` 属于 `SPEC / ARTIFACT / TEXT / PROMPT / SIGNAL / FLOW / ANY`），且 `node skill/check-brick-capabilities.mjs` （私有仓）退 `0`。
4. 新增声明式工作流 `workflows/*.workflow.json` （私有仓）未将任何外部开源项目体积包提交入库，已声明 `deps[]` 或 `install` 供 `workflows/.deps/<id>/` 一键后台补齐，且每条异常支线闭合回主干并设有限循环上限（`maxLoops`）。
