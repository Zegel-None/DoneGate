# 卡 · 适配器实现

**它回答的问题**：怎么把一块砖的上游输出，变成一个合法的 `claim.json`，且不重复手搓协议样板？

规则本体只在 [`skill/17-砂浆适配器协议.md`](../../skill/17-砂浆适配器协议.md)；公共执行底座在 `skill/adapters/_shared.mjs`。本卡只写怎么调用公共底座、按什么顺序填空、什么算过。

## 入口条件

- 候选已选定，接法是 **A（完整接入用到全部）** 或 **B（完整接入只消费部分能力）**。
- 上游 CLI 在本机可跑，且能拿到它的**机器可读输出**（JSON / SARIF / JUnit XML）。
- 知道它归哪一阶段（`stage`）与替哪条判据作证（`checkedBy`）——这两个值**不许自己写死，只能由底座从注册表抄**。

## 步骤

1. **先定注册表条目，再用脚手架生成薄模板。** 在 `adapters.registry.json` 里占一条：`id`（`<tool>@stage<N>`）、`tool`、`stage`、`role`（`hard`/`soft`）、`checkedBy`（`<契约id>/<判据id>`）、`protocolVersion: "1.1"`、`testedToolRange`、`blindSpots[]`。接着运行 `node skill/new-adapter.mjs <tool> --stage <N>` 生成约 30 行的填空模板。
2. **统一委托 `./_shared.mjs` 的 `runMortarAdapter`，严禁手搓底座。** 具体适配器只负责提供三项工具专属回调：`probeVersion`（实时读版本）、`collectRaw`（执行 CLI 或读 `--raw-report` 夹具）、`summarize`（把上游 JSON 提炼为纯事实 `observation`、`claims`、`unresolved`、`degradedTo`）。**具体适配器严禁直接 `import 'node:crypto'` 或 `'node:child_process'`，严禁手写 `git status --porcelain`，单文件总行数不得超过 `90` 行（`M6` 与 `C6` 门禁直接判红）。**
3. **版本号实时读，不许硬编码。** 在 `probeVersion` 中调用底座传入的 `execTool(['--version'])` 并配合 `semverInRange` 校验 `testedToolRange`；写死版本号等于在砖头升级后继续谎报旧版本。
4. **只吃机器可读产物。** 用 `parseJsonOrFail`、`checkFreshFileOrFail`、`withTempDir` 处理上游 JSON 报告；读不到、解析不了、报告早于源码修改时间——**一律退 `3`**，不要猜。
5. **底座自动封存严格九字段**：`stage`、`tool`、`version`、`role`、`inputs[]`、`artifacts[]`、`claims[]`、`unresolved[]`、`degradedTo`。
   - `sha256` 由底座 `shaBytes` 统一算成 **64 位裸小写十六进制**，不带 `sha256:` 前缀。
   - `claims[]` 每条只留 `{ text, checkedBy }` 两键；结构化细节装入 `observation.json` 并登记进 `artifacts[]`（`kind` 以 `-observation` 结尾）。
   - `unresolved[]` 只装**本次运行**产生的未决项；`degradedTo` 必须是非空退化说明，不许填「跳过」。
6. **退出码只留三值**：`0` 正常产出声明、`2` 协议/契约事故（越权传 `--stage`/`--checked-by`、未登记 id、禁词、版本超界）、`3` 现场故障（脏树、上游缺失/崩溃/超时、JSON 截断）。**永不许返回 `1`**：上游扫出的业务问题一律写进 `claims[]` 再退 `0`。
7. **脏树拒收与禁词自检由底座兜底。** `runMortarAdapter` 落盘前自动校验 `git status --porcelain`（`--dry-run` 除外）并扫描 `verdict/ok/clean/passed/failed/score/ratio/green/red/teeth` 十大禁词，命中即退 `2`。

## 出口判据

1. `node <适配器> --root <项目根> --registry-id <id>` 在干净树上退 `0`，且 `.donegate/adapters/<tool>/claim.json` 存在。
2. `Object.keys(claim).length === 9`，顶层无第十个字段。
3. `node skill/check-declarations.mjs --claim <claim.json> --root <项目根>` 退 `0`（核侧单进程复算哈希通过、无禁词、契约命中）。
4. 传 `--stage 4` 或 `--checked-by x/y` 时退 `2`（越权传参必须被拒）。
5. 上游二进制不存在时退 `3`，而不是崩栈或退 `1`。
6. 适配器源码内**没有硬编码版本号**，且已通过 `./_shared.mjs` 接入、总行数 `<= 90` 行、零直引 `node:crypto` / `node:child_process`（`node skill/check-module-integrity.mjs` 退 `0`）。

## 业界做法参考

| 参考 | 它做到哪一步 | 本卡的差异与两个代价 |
|---|---|---|
| in-toto / DSSE 的「证据外壳」思路 | 把「谁产出了什么、基于哪些输入」做成可验签的封装 | 本卡只借它的形状（输入清单 + 产物清单 + 哈希），不引密钥体系。代价：挡不住持写权限的人整份重造；换来：零依赖、离线可核 |
| Template Method（模板方法控制反转） | 把不变协议骨架收进基座，子类只填差异钩子 | `_shared.mjs` 锁死九步协议流，具体适配器压到 90 行内。代价：底座改动牵连全量砖头（须跑 22 套夹具回归）；换来：小模型无法漏写禁词或哈希步骤 |
| `adr/002`（本项目自己的决策） | 规定适配器只产声明、不产状态 | 本卡是该 ADR 的落地工序。代价：核侧必须多做一次复算与裁决；换来：状态只有一个来源 |
