# 卡 · 适配器实现

**它回答的问题**：确定了项目的普适形态（`scanner` / `generator` / `ui-extract` / `runtime-service` / `knowledge-skill` / `aggregator`）之后，怎么用最薄的代码写出合规的 `skill/adapters/<name>.mjs`？

规则本体在 [`skill/17-砂浆适配器协议.md`](../../skill/17-砂浆适配器协议.md)；公共运行底座在 `skill/adapters/_shared.mjs`。所有具体适配器统一委托 `runMortarAdapter`，单文件保持在 `90` 行以内，零手搓协议样板。

## 入口条件

- 已按 [`卡-普适提取与卡片封装.md`](卡-普适提取与卡片封装.md) 定好该项目的 `archetype`、提取通道与 `bricks/<tool>/capabilities.json` 卡片端口。
- 明确它在当前开发流里的阶段号 `stage`（支持 `1–20` 整数）与 `checkedBy`（`<契约id>/<判据id>`，若暂作开发流建议节点可先设为 `advisory`）。

## 步骤

1. **先用多形态脚手架一键生成骨架，不从空白文件手写。**
   - 生成卡片配置：`node skill/new-adapter.mjs <tool> --archetype <形态> --repo <owner/repo> --card-json > bricks/<tool>/capabilities.json`
   - 生成适配器代码：`node skill/new-adapter.mjs <tool> --archetype <形态> --out skill/adapters/<tool>.mjs`
   - 在 `adapters.registry.json` 登记条目（`id`、`tool`、`stage`、`role`、`checkedBy`、`protocolVersion: "1.1"`、`testedToolRange`、`blindSpots[]`）。

2. **按项目形态选用 `_shared.mjs` 的运行模式（`mode`），绝不硬卡无二进制项目：**
   - **默认二进制模式（省略 `mode` 或 `mode: 'binary'`）**：适用于本地可调 CLI 的检查器、无头构建器或一次性容器探针。底座自动完成跨平台路径查找（含 Windows `.exe/.cmd/.bat`）、`--version` 实时提取与 `testedToolRange` 核验。
   - **产物提取与多源归并模式（`mode: 'artifact'`）**：适用于**覆盖族归并卡（`aggregator`）**或**读取带 UI 工具静态落盘产物的适配器**。无需本机安装同名二进制，直接用 `ctx.hashInputFiles` 与 `ctx.checkFreshFileOrFail` 校验上游报告或构建产物并提取摘要。
   - **无二进制知识/规则包模式（`mode: 'knowledge'`）**：适用于设计系统 Usage 指南、Agent 技能集、交互模式决策表等纯规则资产。底座免除二进制探测，自动读取包版本或 `--tool-version`，用 `ctx.hashInputFiles` 锁死规则文档与决策表的 SHA-256 指纹。
   - **自定义探测模式（`mode: 'custom'` 或自定义 `resolveVersion(ctx)`）**：适用于通过 HTTP API 采集运行态服务（如本地 Mock 服务、监控指标端点、Docker 容器内工具），由 `resolveVersion` 从服务端健康接口或配置锁文件实时读取真实版本号。

3. **生成器与带 UI 去壳导出项目，用 `extraArtifacts[]` 锁死产出物链路。**
   对于产出了 SBOM、迁移 SQL、SDK 代码、设计令牌或组件统计清单的 `generator` / `ui-extract` 适配器，在 `collect(ctx)` 返回对象中附上 `extraArtifacts: [{ path: outRel, kind: '<tool>-export' }]`。底座会自动校验该文件真实存在、计算 64 位裸小写 SHA-256 并写入 `claim.json` 的 `artifacts[]`，供下游卡片安全消费。

4. **严守三条不可妥协的协议红线（由底座自动兜底拦截）：**
   - **严格九字段**：`claim.json` 顶层固定为 `stage`（`1–20`）、`tool`、`version`、`role`、`inputs[]`、`artifacts[]`、`claims[]`、`unresolved[]`、`degradedTo`。
   - **零状态禁词**：`claim.json` 与 `observation.json` 内禁止出现 `verdict / ok / clean / passed / failed / score / ratio / green / red / teeth` 键名——只陈述客观数字、产物字节数、去重后条目数或枚举状态名。
   - **三值退出码**：`0` 正常产出声明、`2` 协议或传参越权（如偷传 `--stage` / `--checked-by`）、`3` 现场无法判断（脏工作区、上游缺失/超时、产物不存在或 JSON 截断），**永不返回 `1`**。

## 出口判据

1. 本地调试 `node skill/adapters/<tool>.mjs --registry-id <id> --dry-run` 退 `0` 并打印合法九字段 `claim` 与 `observation`。
2. 干净 Git 树实跑落盘后，`node skill/check-declarations.mjs --claim .donegate/adapters/<tool>/claim.json --root .` 退 `0`。
3. 越权传 `--stage` 或 `--checked-by` 必退 `2`；输入产物缺失、截断或上游不可达必退 `3`。
4. 适配器总行数 `<= 90` 行，未直接引用 `node:crypto` 或 `node:child_process`（`node skill/check-module-integrity.mjs` 退 `0`）。
