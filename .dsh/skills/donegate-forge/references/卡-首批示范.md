# 卡 · 首批示范（biome 与 ast-grep 的真实链路）

**它回答的问题**：前面四张卡说的流程，在一真实砖头上长什么样？

本卡用本仓 2026-11-20 接入的两块砖做示范。**里面的版本号、退出码、JSON 字段都是本机实测的**，不是转述 README。复现命令都在文末。

## 一、示范一：`biome`（JS / TS 静态检查）

### 第 1 步 · 缺口句

> 缺「JS/TS 语法与可疑写法」的机器读数；现在靠人读 diff 兜；补上后 **`biome@stage4` 的 `claims[0]` 能给出 errors / warnings 计数**，判据不再是「无法判断」。

### 第 2 步 · 调研事实（实测档）

| 项 | 实测结果 |
|---|---|
| 版本 | `biome --version` → `Version: 2.6.8`（**注意前缀是 `Version: `，正则要抽 `\d+\.\d+\.\d+`**） |
| 机器可读输出 | `biome lint --reporter=json <dir>` → stdout 是单个 JSON 对象 |
| 退出码语义 | **有诊断时退 `1`，干净时退 `0`** —— 与「跑不起来」同形，必须由砂浆自己归一化 |
| JSON 结构 | `{ summary: { errors, warnings, matches, changed, unchanged, … }, diagnostics: [ { severity, category, message, location: { path, start: { line, column } } } ], command: "lint" }` |
| 噪音 | stderr 有一行「`json` 与 `json-pretty` 报告器为实验特性」的提示；**解析只读 stdout**，别把它当错误 |

### 第 3 步 · 选型判定

接法 **B（完整接入，只消费部分能力）**：只用 `summary.errors`、`summary.warnings` 与 `diagnostics[].category` 三类，不消费 `advices`。`role` 定为 `soft`——它是结构告警，不代表业务正确性，所以**不阻断门禁**。

### 第 4 步 · 造适配器的三个要点

1. **退出码归一化**：`status === 0` 或无诊断 → 退 `0`；`status === 1` 且 stdout 可解析 → 仍退 `0`（把违规写进 `claims[]`）；解析失败 → `3`；`--registry-id` 非法 → `2`。
2. **版本实时读**：每次运行都调 `biome --version` 抽版本号，代码里不出现 `'2.6.8'` 这种常量。
3. **`checkedBy` 抄自注册表**：条目写 `biome@stage4`，`checkedBy` 是 `c01/crit-lint-clean` 这类契约/判据引用，**代码里不许自己写死**。

### 第 5 步 · 五组夹具的期望

| 组 | 造法 | 期望 |
|---|---|---|
| ① 正样本 | 临时项目放一个 `x == 1` 的文件，真跑 biome | 退 `0`，`claim` 九字段，`summary.errors + warnings ≥ 1` |
| ② 映射反转 | 把「有诊断」的 JSON 改成 `diagnostics: []` 后喂 `--raw-report` | 核侧比对出「声称有违规但产物说没有」，必红 |
| ③ 上游缺失 | `--bin __no_biome__` | 退 `3` |
| ④ 产物截断 | 喂 `{"summary":{"changed":0` | 退 `3` |
| ⑤ 非法 id | `--registry-id bad@stage4` | 退 `2` |

### 第 6 步 · 登记

注册表一条 `biome@stage4`（`role: soft`、`testedToolRange: ">=2.6.0 <3.0.0"`、`blindSpots: ["只覆盖 JS/TS 语法与可疑写法，不判断业务正确性；不替代测试"]`），`ledger` 一条 `actionsChanged: 1`，`batches.jsonl` 记一行。

## 二、示范二：`ast-grep`（结构搜索）——**退出码是反的**

| 项 | 实测结果 |
|---|---|
| 版本 | `ast-grep --version` → `ast-grep 0.51.3`（**不是 `sg`，`sg` 已弃用**） |
| 机器可读输出 | `ast-grep run --pattern '<模式>' --lang js --json=pretty <dir>` → stdout 是**匹配数组** |
| 退出码语义 | **grep 语义：匹配到退 `0`，没匹配退 `1`** —— 与 biome 正好相反 |

**这正是砂浆存在的理由**：同一件事，两块砖的退出码语义相反。适配器必须把两者都归一成「业务违规退 `0`（写进声明）+ 现场故障退 `3`」，否则核侧会把「没发现问题」当事故、把「发现问题」当通过。

判别式只有一句：**`status === 0` 表示「有匹配」，`status === 1` 表示「无匹配」，其它非 0 才是故障（退 `3`）**。这一条写进适配器注释，别让下一个人凭直觉改回去。

## 三、复现命令（只读，可随时重跑）

```powershell
biome --version
$env:TEMP\d | Out-Null; md $env:TEMP\d
'function f(x){ if (x==1) { return true } return false }' | Set-Content $env:TEMP\d\a.js
biome lint --reporter=json $env:TEMP\d; echo "exit=$LASTEXITCODE"

ast-grep --version
ast-grep run --pattern 'function $F($$$A) { $$$B }' --lang js --json=pretty $env:TEMP\d; echo "exit=$LASTEXITCODE"
```

## 出口判据

1. 你能照着本卡在自己的机器上复现出**同样的退出码语义**（biome 有诊断退 `1`；ast-grep 无匹配退 `1`）。
2. 你能指出本卡示范里「哪一处是砂浆必须做的归一化」——答不出说明还没读懂第 4 步。
3. 两块砖的注册表条目都能在 `adapters.registry.json` 里查到，且 `blindSpots[]` 非空。
