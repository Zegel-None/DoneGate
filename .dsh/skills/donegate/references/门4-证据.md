# 门4-证据

本卡管：一次运行怎么留证、判有效、上游变了怎么标。

## 入口条件

- 判据已冻结并有签字，`claim` / `observable` / `scope` 三件套齐（定义在 §6.1，§四 里没有）。缺一项不进本门。
- 工作区干净：`git status --porcelain` 输出为空。输出非空就拒绝运行，不先跑再补记录（§8.2.2）。
- 本次要装载的判据哈希，从冻结记录按标识独立取出；不复用运行记录里的 `frozenCriteriaHash`（§8.2.2 ②）。
- 门 3 的变异体状态已落定（killed、survived 等，取值以 §6.1 唯一清单为准），否则「通过」分不出算数 / 无牙 / 未做实验。
- 命令跑不起来、材料读不出：不换命令，按退出码 3 收（§八）。
- **纯技能版没有独立的 freeze/implement 台账**：冻结基准按标识从 `contract.json` 里该判据的 `frozenHash` 取（它就是唯一冻结记录）；`run.head` 记当前干净 HEAD（这次运行跑的提交）。出口 4 的 `implement` 记录缺失时，**把「无法判断」落盘成 end.json 的固定块**——`"implementBinding": { "status": "无法判断", "note": "无独立台账，取不到 implement.versionRange.head" }`，**不许只留在对话或说明文字里**（交接与复核只认文件）；门 3 变异体状态缺失时同理，在 start.json 标 `"mutateStatus": "无法判断"`。

## 步骤

1. 先写 `start.json`，必含项按 §2.6 填齐；同时记 `run.head`，它是这次运行跑的提交，不是仓库当前 HEAD（§8.2.2 ③）。
2. 用第 1 步之前独立取出的判据哈希核对本次装载的判据，不符即停，本次不作数（§8.2.2 ②）。
3. 直跑 `node scripts/…`，不经 `pnpm run` 或 `pnpm exec`。退出码按 §八 四值记：0 通过、1 判否、2 事故、3 无法判断；2 与 3 不许互相顶替。
4. 写 `report.json`，必含项按 §2.6 填齐，并写入 `start` 的哈希。
5. 收尾写 `end.json`，写入成功或失败与 `report` 的哈希。三份按 start → report → end 的顺序落盘，事后补写不认。
6. 复核哈希链：`report→start`、`end→report` 两段都要重算对得上。断任何一环，整份判「无法判断」，该次不算有效运行（§2.6）。
7. 上游有变更时按 §十一 改状态：自己的代码、自己的判据、直接依赖、底座各走对应那一档；传递依赖仍是「通过」但标「待重验」，**不计入「通过数」**——注意「通过数」专指算数（A1），「通过 A」是六栏之一、含 A4，两个数不同名不同义（§3.4 有定义表，别读混）。清标记只认 §11.2 那一条理由；「重跑仍通过」、`conclusionHash` 没变、变异实验有牙，三条都不许用来清（§11.2）。
8. 证据里出现的数字与断言按 §15.8 写：显式统计数字后挂 `<!-- recalc: 命令 -->`；全称断言后挂 `<!-- assert: exit=… && stdout=… -->`，只写退出码不算（§15.8 4.4b）；`assert` 里的命令只许引用已登记的**人签**判据 ID（§15.8 4.4b 的原文是「已登记的人签判据」；未签判据的命令不许内联）。
9. 交给门 5：`verify pack` 出复核包，证据不全得 3；`verify apply` 记结论，门 5 不过得 1、复核包被篡改得 2、判方材料不全或弃权理由不成立得 3（§八）。

## 出口判据

1. 每条判据目录下 `start.json` / `report.json` / `end.json` 三份齐，重算两段互哈希全对。缺一份或任一段对不上，判「无法判断」。
2. **运行器过了两条隔离探针**（§四）：越界读（读项目根之外的文件）与越界连（连外网）**两条都必须失败**；任一条成功即运行器不合格，门 4 不过。声明 `isolation: none` 的允许过，但每条证据旁要标「本次运行无隔离」。
3. `report.json` 的退出码只取 0 / 1 / 2 / 3，且与命令实际退出码相等。出现别的值，或两者不等，本次证据作废并给出退出码 2（事故）。
4. `run.head` 与 `implement` 记录的 `versionRange.head` 相等（`versionRange` 是 `implement` 记录的字段，不是 `freeze` 的——两条记录别混）。不等即这条证据不绑定本次实现，退出码 3；拿 `git rev-parse HEAD` 的结果顶上来，按 §8.2.2 ③ 判红。
5. 「待重验」的判据在六栏总账里落在通过四分的待重验一栏，不落进算数一栏。拿重跑仍通过把它填成算数，判红（§十一 11.2）。
6. 文档里每处显式统计数字都紧跟可重算的 `recalc` 命令（**四条豁免**：围栏代码块内、表头标了「阈值/上限」的设计参数、日期与版本号、标题里的编号——这四类不要求挂命令），每处全称断言都紧跟同时写期望退出码与期望输出的 `assert`。缺一条或只写退出码，判不通过（§15.8 4.4a、4.4b）。
7. 复核包出得来：`verify pack` 得 0，证据不全时得 3 而不是 0；`verify apply` 在指纹链断时得 2，在判方材料不全或弃权理由不成立时得 3。把门 5 不过记成通过，判不通过。

## 业界做法参考

| 参考 | 做到哪一步 | 本卡的差异与两个代价 |
|---|---|---|
| cosign（I4 首选） | **部分**：能发现任何对证据与签名的改动，但**持有私钥或身份的人仍可重签**（解法册 I4 原话）——所以它挡的是「手改」不是「造假」 | 同一个量是「一次证据要人做几步」：本卡 0 步（三份文件互哈希，零密钥、离线）；cosign 每份证据多 1 步密钥操作加 1 步签发方校验；代价：本卡挡不住持有写权限的人整份重造（范围：全部证据可绕过）另配）。差一步，本卡接受。 |
| immudb（I4 备选） | 证据只能追加进密码学日志，改盘由客户端根哈希暴露 | 本卡证据仍是明文文件，靠 `end.json` 的哈希互相咬住；本卡代价是整份重建无外部见证；immudb 的代价是读证据要改走验证接口，本地证据不再是纯文本。 |
| execa（I6 首选） | 子进程非 0 默认 reject，退出码成必处理字段 | 本卡不做进程封装，用「只直跑 `node scripts/…`」这条操作纪律代替；本卡代价是纪律靠人守、漏一次就吞码；execa 的代价是多一层依赖，且管不到上游 shim 自己吃码。 |

差异口径见 adr/015（调研/评审材料，不在公开分发包内）。
