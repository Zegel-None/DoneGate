# 交接包

**这张卡管什么**：它管的是「这一轮结束时，交给下一个人或下一个会话的东西够不够用」。状态必须由命令现算，不许手写；交接包里必须带一条接收方实跑记录。规则本体在 规格（调研/评审材料，不在公开分发包内） 的 §九 阶段 6 与 §15.0 门 0.4 里；本卡只写怎么生成、按什么顺序、什么算过。

## 入口条件

| 编号 | 条件 | 不满足时 |
|---|---|---|
| 1 | 本轮已经到阶段 6 | 阶段 1–5 不做交接，直接结束本轮 |
| 2 | 先跑一次 `handover`，它的退出码是 0 | 退出码是 3 表示状态算不出来，此时去补材料，不许手填 |
| 3 | 项目在阶段 6 时门 0.4 生效：`HANDOVER.md` 六节齐，且含一条非空的接收方验收记录 | 缺节或字段为空，门 0.4 不过 |
| 4 | 手边有 `INTENT.md`、`CONSTRAINTS.md`，以及当场跑出的 `status` 总账 | 缺材料时先补齐，再生成交接包 |

## 步骤

1. **生成，不手写。** 跑 `handover`（§八），拿到六节：当前状态、下一个该做的、未定事项、最近三条决策、已知缺口、怎么跑起来。节名与节序照命令输出抄，不加节也不改名；实例见 03-走查.md（调研/评审材料，不在公开分发包内） 第 21 天。
2. **第一节贴状态。** 六栏总账与通过四分逐格照命令输出抄（§三）。六栏相加要等于总项数，加不起来就是算错，不许凑。也不许凭会话记忆报数。
3. **第二节写下一件事。** 从 `gaps` 里只挑一条，写清是哪条契约、哪条判据；判据要带 `claim`、`observable`、`scope` 三项，缺一项接收方就跑不起来。如果挑的不在缺口前 3 位，就要写 `skipReason`（§15.0）。
4. **无牙与未做实验的项要带证据线索。** 附最近一次 `teeth` 的变异体状态（§六、§八）。**没做过实验的写「未做实验」（A3，状态仍是「通过」）**，不许写成「无法判断」，因为那是材料读不出来的事故态（§3.4.1）。留空按没写算。
5. **第六节写怎么跑。** 三条命令要能原样粘贴：冒烟、该契约判据、`status`。写子进程直跑的形态，不写经过 `pnpm` 的形态（[SKILL.md](../SKILL.md) 第五节）。当前档位（T0 / T1 / T2）也写在这一节（§九）。
6. **交给接收方跑一遍。** 找一个没参与本轮的人或一个全新会话，让它对一个真实使用场景跑一次，然后把结果写进第六节末尾的固定子块 `### 接收方验收记录`。这个子块有四要素，缺一个就算空：谁跑的、跑的命令原文、看到的输出、卡住的格（G-05）。只复述文档不算数（§九 阶段 6 ②）。
7. **再做十分钟实测。** 题本固定四问：现在做到哪、下一步做什么、怎么验证、这份文档不覆盖什么。逐问作答并计时；结果与接收方验收记录一起留在仓库文件里，下一轮开工只认文件。

## 出口判据

| 编号 | 判什么 | 不过的样子 |
|---|---|---|
| 1 | `handover` 退出码为 0 | 出现 3 就是失败；状态算不出来该去补材料，不该手写补数（§八） |
| 2 | 六节齐、节名与命令输出一致，且接收方验收记录非空 | 缺节或字段为空（判法见 §15.0 的 0.4） |
| 3 | 十分钟实测：3 个没参与过的会话只给 `HANDOVER.md`，计时答四问 | 有 1 个没答全四问，或中位耗时超过 10 分钟（口径见 06-验证方案（调研/评审材料，不在公开分发包内）） |
| 4 | 题本不许改 | 换成三问、五问，或用「看懂了吗」代替逐问作答；第四问答成「都覆盖了」也判失败 |
| 5 | 总账可复现 | 把第一节六栏与当场 `status` 输出逐格比对，有一格不同就失败（§三） |
| 6 | 命令可粘 | 照第六节原样粘进新会话，有一条要改路径、补参数或跑不起来 |

## 一个必须照抄的子块

```text
### 接收方验收记录
- 谁跑的：
- 跑的命令原文：
- 看到的输出：
- 卡住的格：
```

这四行是门 0.4 的判定依据，也是 G-05 的落地位置。四行里任何一行留空，交接包都不算完整。

## 业界做法参考

| 参考 | 它做到哪一步 | 本卡与它的差异 |
|---|---|---|
| GitHub Spec Kit（E5 首选） | 它把需求、取舍与验收结论固化成版本库里可 diff 的文档，最后一步的 handoff summary 直接交给下一阶段 | 它交的是一份摘要；本卡要六节加固定四问，一份摘要不算交出去 |
| Cline Memory Bank（E5 第 2 条） | 它用固定结构的 `memory-bank/` 承载当前焦点与进度，会话开头读、有变化回写 | 它靠 agent 自觉回写；本卡的状态由命令现算，写错会在总账复现那一步被抓到 |
| beads（H5 首选） | 它把现状放进 Dolt 依赖图，agent 的 claim 与 close 就是人看到的同一份状态 | 它要装 CLI 并靠 push / pull 同步；本卡不引外部状态库 |

**两处差异各付什么代价**（口径见 adr/015（调研/评审材料，不在公开分发包内））：交接耗时方面，Spec Kit 写一份摘要按十分钟算，本卡要六节加 3 个会话实测、按单次 1 小时估，于是多花约 2 小时；外部依赖方面，beads 用单一状态源换掉两边对齐，代价是要装 CLI 加同步，而本卡零外部依赖，代价是每次交接都得重算一次状态，算不出来（退出码 3）时交接根本做不下去。
