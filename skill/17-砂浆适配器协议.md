# 17 · 砂浆适配器协议 v1.1（Mortar Protocol v1.1 · 终稿）

**定位**：本协议是 V4 所有外部开源工具（砖头）接入**判定核（门禁层）**的唯一接口契约。任何适配器（位于 `skill/adapters/<name>.mjs`）必须完整遵守本协议，否则禁止入网。

**上位依据**：ADR-002 适配器只许产出声明，不许产出状态（调研/评审材料，不在公开分发包内）、02-规格.md（调研/评审材料，不在公开分发包内） §五（总线记录格式）与 §八（四值退出码）、10-规格缺口定论（技能版）（调研/评审材料，不在公开分发包内） G-09 / G-12。

---

## 一、边界定义：判定核、砂浆、旁路层与「冻结」

1. **判定核（门禁层）**：零第三方依赖、Node 原生直跑的确定性核心脚本集合，是全仓**唯一有权产出五态、评级与业务通过/未通过结论的层**。当前入口：`runner/run-criterion.mjs`、`runner/engine.mjs`（待建）、`skill/schema-lite.mjs`（待建）及既有 `skill/check-*.mjs` （私有仓）零依赖必跑判据。
2. **砂浆（适配器）**：位于 `skill/adapters/<name>.mjs` 的薄转换层（仅用 Node 原生模块），只负责读取或调用外部砖头并将其原始输出归一化为客观观测声明（`claim.json`）。**砂浆绝不产出状态、评级、分数或业务通过/未通过结论。**
3. **脚本分层边界（严守 `02-规格.md` §八 十二条冻结）**：`skill/check-declarations.mjs` 与 `skill/check-brick-liveness.mjs` 属于 V4 适配器治理的**「按场景跑」旁路检查层**（仅在接入外部砖头时按场景执行），保持零依赖 Node 直跑，**不计入、不扩充、不替代十二条必跑判据**。
4. **二期砖头「冻结 ≠ 卸载」**：`spec-kit`、`OpenSpec`、`fuck-u-code`、`jscpd`、`gitleaks`、`osv-scanner` 等标注为「当前冻结」，**冻结仅指暂不接入判定链（不进 `adapters.registry.json` 与 `ledger.json`），不等于卸载**；本机已装好的环境保持原样不动。

| 路径 | 职责 | 是否入 Git |
|---|---|---|

## 三、严格九字段结构（一字节不超 `02-规格.md` §五）

适配器产出的 `claim.json` 顶层**只许包含以下九个字段，多一个都不许**。`id`、`at`、`durationMs`、`fingerprint`、`accepted` 归总线或判定核侧写入，适配器严禁自填。

| 字段 | 类型 | 必填 | 语义与硬约束（对齐 `02-规格.md` §五） |
|---|---|---|---|
| `stage` | `1..20` | ✅ | 正整数 `1–20`（兼容核心 `1–7` 阶段与 `1–10`+ 全周期扩展开发流）；**仅从 `adapters.registry.json` 按 `--registry-id` 抄录**，严禁 CLI 传 `--stage` |
| `tool` | string | ✅ | 上游工具规范名，必须已在 `adapters.registry.json` 注册 |
| `version` | string | ✅ | 运行时从上游实测读取的版本号（**代码内禁止硬编码固定字符串**，须由 `--version` 或 `package.json` 实时读取） |
| `role` | `"hard" \| "soft"` | ✅ | `hard`：进入门禁计算；`soft`：仅给人读，故障不阻断门禁 |
| `inputs` | object[] | ✅ | 参与本次运行的源码/输入清单，每项 `{ path, sha256 }` |
| `artifacts` | object[] | ✅ | 真实存在的产物清单，每项 `{ path, sha256, kind, bytes? }`（含原始报告、`observation.json`、`git-anchor.json`） |
| `claims` | object[] | ✅ | **严格且仅含两键** `{ text, checkedBy }`（对齐 §五 L414）；结构化观测数据放 `observation.json` |
| `unresolved` | object[] | ✅ | **仅装本次运行产生的未决项**，每项 `{ text, stage }`（`stage` 为 `1–20`，不许写「以后」）；无则 `[]` |
| `degradedTo` | string | ✅ | 工具缺席时的退化方案（**必填非空字符串，不许为 `null`，不许填「跳过」**） |

## 四、核心防自欺条款（Q1–Q10 与 M2 / J3 定稿）

1. **绑定锁死（Q1 · 阶段与 `checkedBy` 只许抄不许选）**：
   - 跨阶段工具在 `adapters.registry.json` 中按阶段分条注册（如 `stryker@stage4`、`stryker@stage5`），每条冻结 `stage`（`1–7`）与 `checkedBy`（`<contractId>/<obligationId>`）。
   - 适配器禁止接收 `--stage` 或 `--checked-by`，**只接收 `--registry-id <id>`**，运行时从入库的 `adapters.registry.json` 原样抄录 `stage` 与 `checkedBy`。缺失、未登记或语法非法直接退 **`2`**。
2. **契约查找与歧义处理（`check-declarations.mjs` 执行）**：
   - 解析 `<contractId>/<obligationId>` 时，同时存在 `contracts/` 目录与根 `./contract.json` → **布局歧义，强制退 `2`**；两者皆不存在 → 退 **`3`**。
   - 仅存在 `contracts/` 时只读 `contracts/<contractId>/contract.json`；仅存在根 `./contract.json` 时核对顶层 `id === <contractId>`（不匹配退 **`1`**）。文件读不出/损坏退 **`3`**；查无 `<obligationId>` 退 **`1`**（按 §五 进缺口）。
3. **哈希规范与核侧单进程复算（G-09 / Q2 / Q7）**：
   - 所有 `sha256` 必须为整文件原始字节的 **64 位裸小写十六进制**（`^[0-9a-f]{64}$`），**禁止加 `sha256:` 前缀**。
   - 适配器填的哈希仅作承诺线索；判定核读取 `claim.json` 时必须在**单进程一次读盘**中将 `claim.json` 及全部 `inputs[]`/`artifacts[]` 读入内存、立即对内存字节独立重算 SHA-256，后续只消费内存对象不再二次读盘。文件读不出退 **`3`**，重算哈希不符退 **`2`**（遵守 INV-10 不降级）。
4. **干净树锚定与 `--dry-run`（Q5）**：
   - 正式落盘前必须先跑 `git status --porcelain`。输出非空即脏工作区，**一律拒收退 `3`**（不产出可进门禁的 `claim.json`，提示先 `commit` 或 `stash`）。
   - 仅当工作区完全干净时，将 `{ "head": "<git rev-parse HEAD>", "worktreeHash": "<git rev-parse HEAD^{tree}>", "isDirty": false }` 写入 `.donegate/adapters/<tool>/git-anchor.json` 并登记进 `artifacts[]`（`kind: "git-anchor"`）。
   - 开发期本地调试允许传 `--dry-run`：仅打印 stdout，**禁止落盘 `claim.json`、禁止进总账读数**。
5. **防陈旧报告背书新提交（Q3）**：
   - 正式采证入口（`run-stage.mjs`）必须在同一次运行内**先清旧产物、现跑上游砖头、再跑适配器**。
   - 若适配器以离线模式消费已有报告文件，必须校验该报告文件的 `mtime` 严格晚于当前 `HEAD` 提交时间（且报告涉及的源码路径与 `inputs[]` 一致），过旧直接退 **`3`**。
6. **运行时未决项 vs 静态固有盲区（Q4）与 `role: soft` 语义**：
   - `unresolved[]` **只装本次运行实际产生的未决项**（如本次出现 `Ignored`/`Pending` 变异体或文件解析失败）。`role: "hard"` 只要 `unresolved[]` 非空，不得进入 `A1 算数`；`role: "soft"` 退 `3` 或 `unresolved[]` 非空均**不阻断门禁**，仅输出可见告警。
   - 工具形态固有盲区（如 Stryker 档 B 无法测 `red-wrong-assertion` 与 `restore-failed`）不塞进 `unresolved[]`，而是静态登记在 `adapters.registry.json` 该条目的 **`blindSpots[]`** 中，由视图与门 5 复核包永久透传展示。
7. **禁词红线与幂等性**：
   - `claim.json` 与 `observation.json` 顶层及条目中严禁出现状态/评分键名：`verdict`、`ok`、`clean`、`passed`、`failed`、`score`、`ratio`、`green`、`red`、`teeth`。
   - 对同一份上游原始产物重跑适配器，`claim.json` 与 `observation.json` 必须字节级一致（不含时间戳）。
8. **版本漂移分退码（Q9）**：
   - `adapters.registry.json` 每条钉死 `protocolVersion` 与 `testedToolRange`。协议版本不兼容退 **`2`**；外部砖头升级超出 `testedToolRange` 退 **`3`**（须重跑三组必红夹具并更新注册表后放行）。
9. **M2 提示注入禁令**：
   - 适配器与判定核脚本**严禁将任何外部说明文件（`README.md`、`AGENTS.md`、外部文档）原文拼接进 shell 命令字符串或 `eval`**，防止说明文件成为命令/规则注入入口（与 G-12 探针协同覆盖 M2）。
10. **J3 过程信号消费**：
    - `run-criterion` 与适配器产物保留耗时、`stdout/stderr` 哈希、8 态变异分布及 `unresolved[]`；总账旁注**固定打印「不稳定栏计数 + `unresolved` 计数」**，不把过程信号折叠进单一通过率。
11. **诚实边界声明（Q10 · 同源共谋边界）**：
    - 本协议防的是无意偷懒、上游静默失效与适配器越权报绿；**单靠本协议防不住「同一个人或同一会话同时篡改适配器、判定核与三组夹具」的故意共谋**，也防不了单机用户同步篡改磁盘文件并重算哈希。该层摩擦力来自协议外的三道既有机制：门 5 异构模型审 `base..head` diff、独立第三方盲判/红队复核、以及 ADR-007 同源结论强制降档。

## 五、适配器退出码三值表（彻底取消 `exit 1`）

**架构铁律**：砂浆适配器本身**永不返回 `exit 1`**。上游扫出的任何业务违规（循环依赖、变异存活、密钥命中）均作为客观观测写入 `observation.json` 与 `claims[]` 并退 **`0`**，由判定核裁决 `0` 或 `1`。

| 退出码 | 语义 | 触发条件 |
|---|---|---|
| **`0`** | 正常产出合法声明 | 工作区干净、上游运行成功且原始输出完整解析，合法九字段 `claim.json` 与 `artifacts[]` 已落盘 |
| **`2`** | 确定性协议/契约事故 | `--registry-id` 缺失/未登记、schema 违规、坏类型、未知枚举、出现状态禁词、`protocolVersion` 不兼容 |
| **`3`** | **无法判断（上游/现场故障）** | 脏工作区、上游二进制缺失/崩溃/超时、报告过旧、JSON 截断或关键字段缺失、工具版本超出 `testedToolRange` |

## 七、核侧统一夹具验收、执行器自测与 3 批淘汰（Q6 / Q8）

1. **三组必红夹具进核侧统一跑（Q6）**：每个新适配器的三组夹具（映射反转致核必红 / 上游缺失退 `3` / 产物截断退 `3`，另附 1 条非法 `--registry-id` 退 `2`）统一落盘 `tests/adapters/（私有仓）<tool>/`，由核侧旁路入口 `node skill/check-declarations.mjs --verify-adapters` 一键全量真跑；新砖合入时，门 5 判方必须直接查看该命令的原始实跑输出。
2. **执行器固定反例自测（Q8）**：`run-stage.mjs` 配固定反例脚本 `tests/adapters/run-stage-self-test.mjs`（私有仓），至少验证三例：① 假适配器退 `3` 时绝不吞码、原样退 `3`；② 假适配器输出禁词时拦截退 `2`；③ 脏 git 临时仓拒收退 `3`。由人或门 5 判方直跑作为确定性终点，不建更高层套娃。
3. **3 批硬淘汰制**：每块砖入网记入 `ledger.json`（`{ brick, wiredAtBatch, actionsChanged }`）；连续 3 批 `actionsChanged === 0` 强制拔除接线。

## 八、普适开源项目扩展：六类形态、免二进制模式与画布卡片/开发流协议

为确保任意 GitHub 开源项目（含自带 Web UI 工作台、纯生成器、常驻容器/状态机、无二进制设计规则/Agent 技能包及覆盖族归并器）均可无损接入而不被单一 CLI 假设卡死，协议提供以下向下兼容扩展（详见工坊卡 `donegate-forge/references/卡-普适提取与卡片封装.md`）：

1. **六类普适形态（`archetype`）与「去壳取核」**：
   - `scanner`（诊断探针）、`generator`（工件生成，经 `extraArtifacts[]` 绑定生成物 SHA-256）、`ui-extract`（带 UI 项目去壳提取：优先无头 CLI 导出 → 次选后台 HTTP/JSON 快照 → 兜底静态产物监听，绝不在卡片内嵌套对方前端 UI，仅可选填 `upstream.uiExternalUrl` 外跳查看）、`runtime-service`（容器/Mock/枚举状态机一次性探针与快照）、`knowledge-skill`（无二进制规则/技能/决策表资产）、`aggregator`（互补覆盖族多源报告去重归并）。
2. **公共底座免二进制运行模式（`_shared.mjs` `spec.mode`）**：
   - `binary`（默认，自动探测跨平台可执行文件并实读版本）、`artifact`（免二进制，专供产物校验与多源归并）、`knowledge`（免二进制，锁定规则/提示词文件指纹）、`custom`（自定义 `resolveVersion` 适配 HTTP 服务或容器内工具）。
3. **模块化画布卡片与声明式开发流（零前端改码接入完结门工作台）**：
   - `bricks/<tool>/capabilities.json` 支持可选 `archetype`、`upstream` 与 `card`（定义 `inputs[]` / `outputs[]` 七类端口 `SPEC | ARTIFACT | TEXT | PROMPT | SIGNAL | FLOW | ANY` 及功能开关 `slots[]`），由 `runner/atlas/hydrate-workbench.mjs` 自动渲染为画布模块卡片。
   - 仓库 `workflows/*.workflow.json` 支持声明式定义多阶段开发流（含主干连线、异常闭环回跳上限 `maxLoops` 与人工闸门节点），工作台启动或刷新时自动装载。
