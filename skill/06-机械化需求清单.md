# 06 · 机械化需求清单（技能版的产出物之一）

**这份是干什么的**：技能版靠「模型照规矩做」；**它在哪一步靠不住，就是插件版要机械化什么**。本清单是插件版的需求输入，不是技能版的自我批评。

**怎么读**：每条四列——「模型在这一步怎么靠不住」→「现在靠什么按住」→「插件该机械化什么」→「有牙判据（怎么证明它真机械化住了）」。

**状态**：草案。**试点前写的，试点后要按真实读数删改**——没在试点里真栽过的条目，优先级只能算推测。

---

## 一、必须机械化（不做就整条链失效）

| # | 模型怎么靠不住 | 现在靠什么 | 插件要机械化什么 | 有牙判据 |
|---|---|---|---|---|
| M-01 | **状态是模型写的**，可以写错、写假、写完忘了改 | 只剩「如实条款」和自评降一档 | 状态字段由运行器写，模型无权写（INV-01、INV-05） | 造一份手写状态，插件必须拒绝并报冲突 |
| M-02 | 拿 `pnpm` / `npx` 跑判据，**取到的是包装层的退出码**（原写「吞成 0」，2026-11-19 复测 7 条路径未复现，见 runner/README.md） | 卡里反复警告「子进程直读」 | 运行器取码并原样落证据；包装层调用直接判红 | 造一条 `exit 1` 经包装层跑，插件必须报 1 不是 0。**2026-11-19 试水：本机 7 条路径（pnpm/npm/npx × shell 开关）全部保真，吞码未复现**——见 runner/README.md（调研/评审材料，不在公开分发包内）；`runner/` 因此只做「直读 + 与模型自述对账」（后者能红），**不做包装层判红**。前提措辞待勘误按实测改写 |
| M-03 | **六栏总账加不起来**（写成通过 3、通过里算数 2，剩 1 不知道去哪） | `模板-总账` 卡带三个算例 | 总账现算，四子数与六栏都由分类器派生 | 造一条六栏相加 ≠ N 的总账，插件必须红 |
| M-04 | **四分分类手填**，A1/A2/A3/A4 凭印象 | `tools/classification.json` 是权威，但技能版里仍是模型按表填 | 分类器驱动，优先级顺序写死在数据里 | 把 A1 的 `killed` 改成 `survived`，分类必须全变 |
| M-05 | `teeth` 写成规格外的值，或把 hollow 当成「有牙」 | 唯一清单（11 个值）+ 「未知值退出码 3」 | 取值枚举由 schema 守；未知值走 3 | 注入 `teeth: "mostly-killed"`，必须退 3 不是 0 |
| M-06 | 证据三件套**手工拼**，哈希链断了自己看不出来 | `模板-证据记录` 卡 | 运行器写三份并互相哈希 | 改 `report.json` 一个字节，证据必须判「无法判断」 |
| M-07 | 材料指纹**用当前文件冒充运行时的文件** | `门4-证据` 卡写清 `run.head` ≠ 当前 HEAD | 运行时快照 + `run.head` 独立采集 | 造「干净 H 与脏工作区都标 run.head=H」，插件必须发现 |
| M-08 | 依赖变了**懒得重跑**，直接沿用旧通过 | 「待重验不计入通过数」写在卡里 | 依赖图 + 过期传播机器算 | 改上游一行，下游状态必须自动变待重验 |
| M-09 | 交接包**少写一节**、题本临时改问法 | 四问题本冻结在卡里 | 模板生成六节 + 四问计时器 | 交接包删一节，插件必须红 |
| M-10 | 判方材料**多给了计划/对话**（隔离失效） | `判方材料包` 卡是人工清单 | 打包器按白名单裁切，出现第六类即红 | 往包里塞一份「计划」，打包必须拒绝 |
| M-11 | 判方答出**第四个值**（「差不多」「建议再看看」） | 卡里写死三个值 | 结果 schema 只收 pass/fail/unknown | 提交「大概吧」，必须 `invalid-abstain` 退 3 |
| M-12 | 门 0 / 门 2 的九条**凭记忆勾**，漏了也不知道 | 门 0 卡与门 2 卡逐条列 | 每条一道命令，跑完自动勾 | 造一个缺 `signedBy` 的判据，门 2.2 必须红 |
| M-18 | **写方通过缩小 scope 让判据全绿**（判据是绿的、证据链对得上、总账加得起来，只是不覆盖会坏的行为） | **无**——门2 卡的「不许缩范围」实测无效（W5 三版对比 79.2%→84.2%→84.6%），已撤回 | **判据的覆盖范围不许由写方单独决定**：要么直接取自人给的验收标准原文，要么在冻结前由裁方逐条确认「这条判据不覆盖 X，我认」并留痕 | 构造一个「缩小 scope 后一切合规」的交付，插件必须红（红队 W5 的 q029 就是这种） |
| M-19 | **自述命令清单里的命令可能根本没跑过、或文件根本不存在**（`node _mkevidence.mjs` 没交这个文件、`node -e <verify-evidence-chain>` 占位符） | **无**——W6 实测 8/83 = 9.6% 这样写，而同一批的判据命令本身全诚实 | 运行器自己采集每一次命令调用，**不许模型自述命令清单**；`DONE` 由采集器派生，不由模型写 | 给一份写着「没跑过的命令」的自述清单，插件必须判红 |
| M-20 | **`skipReason` 是契约上的持久字段，可能被当成永久豁免**（§15.0 0.3 只说「不写就不过，写了就过」，没说它只管本轮） | 技能版里靠人写日期自救，机器不判 | 插件把它做成**本轮一次性**：按轮次存、下一轮自动失效；每轮把用到的 skipReason 列进本轮记录 | 造一个连续三轮带同一个 `skipReason` 的契约，插件必须只认第一轮、后两轮判不过 |
| M-21 | **三处哈希归一化没定义**（frozenHash、门0 0.2 的意图/约束哈希、证据链互哈希）：三波被试自发收敛到同一读法，但没有 schema 强制，换个人就可能换算法（skill/10 的 G-09） | G-09 的读法写进卡并由 check-cards 守着；被试间互相可复算 | schema 定死：文件级＝整文件原始字节 SHA-256；frozenHash＝判据对象去 frozenHash/teeth 的 JSON.stringify | 造一个归一化不明的哈希（如带 BOM、带序数键），插件必须红 |

## 四、明确不机械化的（有理由，不是偷懒）

| 不机械化的 | 为什么 |
|---|---|
| 「这个功能该不该做」 | 价值判断，永远是人的事 |
| 「判据守的是不是该守的东西」 | 只能靠有牙实验与判方，机器判不了语义 |
| 「交接包写得够不够好」 | 只能靠十分钟实测与接收方验收 |
| 「判方答得对不对」 | 判方本身就是被判的对象，再套一层会无限后退 |

*本清单的每一条都要在试点里被证伪一次：**如果某个步骤模型一次都没出错，那一条就不该留在「必须机械化」里。** 试点结束后按真实读数删改，别把它当许愿单。*
