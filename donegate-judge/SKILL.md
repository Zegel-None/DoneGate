# DoneGate（完结门）· 判方

写方递来复核包，你只答 `pass` / `fail` / `unknown` 三个值（这就是五项 rubric 的作答），没有第四个值，也不写「差不多」「建议再看看」。五项怎么判见 `../设计/02-规格.md` §七（7.1–7.4）；本卡只说三样：怎么操作、什么顺序、什么算过。

## 入口条件

1. **禁止写方自审，仅限独立只读调起。** 写方会话、执行子代理、模型自动规划都调不动（`disable-model-invocation: true`）。发现同会话自动触发，停手，退出码 `3`（§八 的 `init` 已把「拒绝执行」定为 3：不执行且要人处理）。
2. **先换异构模型。** 判方与写方同模型，同一盲区会在评审里被放过（§7.4）。同模型立即停手并说明，退出码 `3`。
3. **材料齐了才开工。** 复核包要有 §7.4 左列四样：判据原文（含 `expect`）、`base..head`、运行输出与退出码、契约的 `scope` 与 `why`；**再加第五样「完成声称的原文」**——INV-14 规定复核包只许含五类且五类必须齐，少了它 V5（无越界）无判定依据。缺哪样先记下，不许先判后补。
4. **零后果中性审词与跨会话剥离 `<think>`。** 审校提示词只做纯客观技术事实核查，强制剥离扣分、严惩、奖励、重训、淘汰等后果暗示词以消除包庇放水；同时剥离写方 `<think>...</think>`、`reasoning_content`、压缩摘要与自述辩词（§7.4 右列），禁拿写方自辩当 `pass` 理由。

## 步骤

1. **清点材料与提炼契约专属 `SPCT` 核查点。** 按 §7.4 左列清点缺口；先从当前契约 `invariants`、`obligations` 与 `scope` 提炼本次专属正向核查点与非契约排除项，锁定核对基准后再读改动。
2. **扫完全量 `scope` 防首错早停，按固定顺序过五项。** 必须逐一审完 `scope` 内全部受改动文件并在 `auditedFiles[]` 完整列出，严禁抓到第 1 个小错就早停漏审其余高危文件；按 V1 范围 → V2 可定位 → V3 无放水 → V4 无未覆盖 → V5 无越界（§七）逐项指认位置后落值。
3. **V3 先查例外与防放水坏样本校准准则。** 有决策记录写明「原判据无效」的答 `pass`；凡遇放宽断言、删用例、改容差、加跳过（§7.2），以及空操作凑绿（noop）、硬编码特例返回值、吞异常伪造 `0` 退出码、篡改冻结测试哈希或越界偷改，**一律判 `fail`**；对无可达反例的纯代码风格差异不得臆造 `fail`。
4. **填 unknown 前先过 §7.3 两列。** 左列（材料缺、自相矛盾、超出可读范围）才能写，且必须写明缺哪份文件；落在右列就回去给 `pass` 或 `fail`。写不出缺哪份材料即 `invalid-abstain`，退 `3`。
5. **汇总与确定性硬门禁一票否决。** 全 `pass` → `0`；任一 `fail` → `1`；无 `fail` 但有 `unknown` → `3`（§7.1）；只要确定性测试、微门禁或契约锁为红（`exitCode !== 0`），哪怕多票 `pass` 也一票否决为 `fail`。**复核包被篡改与材料自相矛盾都按 §八 与 INV-10 执行（2）退 `2`**（该项作答仍写 `unknown`，见 skill/10（调研/评审材料，不在公开分发包内） G-02）。
6. **凡判 `fail` 必填首错 `targetFile` + `lineRange` 与反例 `proof`（`J-03`）。** 任一维度判 `fail` 时，**强制必填**精确首错文件 `targetFile`、正整数闭区间 `lineRange: [start, end]`（`1 <= start <= end`）及非空 `proof: { premise, executionTrace, conclusion }`；多步状态追踪支持用 `'..'` 继承上一步未变变量槽位防长表抄写幻觉，缺定位或字段直接退 `3` 拒收笼统打回。
7. **交结论与多模型平行共识。** 输出五项作答、`auditedFiles[]`、总结论、缺口清单与退出码，禁改判据、改代码或推状态。关键交付可经 `donegate verify apply <packDir> --votes v1.json,v2.json,v3.json` 汇总异构票据。

## 出口判据

1. 五项各一行，作答值只出现 `pass` / `fail` / `unknown` 三词，出现第四种或少项即失败；`auditedFiles[]` 完整覆盖 `scope` 内全部受改动文件，早停漏审即退 `3` 失败。
2. **凡判 `fail` 的项均附带精确首错 `targetFile`、`lineRange: [start, end]`（`1 <= start <= end`）与非空 `proof`（支持 `'..'` 差量状态追踪），缺任一字段即退 `3` 失败；全程保持零后果中性审词且未引用写方 `<think>`。**
3. **V2 按原定义查：每一条判据都要能定位到改动里的具体位置**，任一条指不出即失败（§七 V2）。
4. 每条 `unknown` 都写明缺哪份文件或材料，写不出的按 `invalid-abstain` 退 `3` 失败（§7.3）。
5. 退出码与结果一致：全 `pass` 却 `1`、有 `fail` 却 `0`、只有 `unknown` 却 `1`、材料自相矛盾却给 `1`、或硬门禁红灯却放行 `pass` 均算失败（§7.1、§八）。
6. 结论无改判据、改代码、推状态字句（§7.4）；记判方模型名备查，与写方同模型即失败。

## 业界做法参考

| 参考 | 做到哪一步 | 与它的差异 |
|---|---|---|
| superpowers 的 `requesting-code-review` 与 `code-reviewer.md`（F2 首选） | 派审阅只给需求与 `base..head`，明令不传作者会话历史与思维链。全覆盖 | 本卡换成 §7.4 给/不给清单，并强制 `fail` 附首错 `targetFile + lineRange` 与 `executionTrace` |
| DeepSeek `SPCT` 动态准则与 OpenAI `evmbench` 全范围审计 | 先按契约派生专属核查点，扫完全量 `scope` 防首错早停。部分覆盖 | 本卡不允许改写冻结判据，仅从契约派生只读核查点并用 `auditedFiles[]` 验全覆盖 |
| Anthropic `Petri` 中性审词与 Canary 20 例调和 `F1` 校准 | 剥离奖惩威胁词消解包庇倾向，用正负样本行号区间与 `harmonicF1` 校准。部分覆盖 | 本卡叠加确定性硬门禁一票否决与 `'..'` 紧凑差量状态追踪，保持只读不改码 |

**两个代价**（adr/015（调研/评审材料，不在公开分发包内））：改成 AdaRubric 式现场改写判据维度，在「冻结判据与任务对不上」情境下每轮省约 1 次改判据重签（次数）；但同一改动两次判会得到不同底线，与判据冻结及哈希链（§八）冲突。本卡反向付：只派生契约内核查点而不改判据，判据写坏时每轮多 1 次冻结签收（次数）。按同一量比，本卡选可重复那侧。
