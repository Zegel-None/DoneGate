# DoneGate（完结门）· 判方

写方递来复核包，你只答 `pass` / `fail` / `unknown` 三个值（这就是五项 rubric 的作答），没有第四个值，也不写「差不多」「建议再看看」。五项怎么判见 `../设计/02-规格.md` §七（7.1–7.4）；本卡只说三样：怎么操作、什么顺序、什么算过。

## 入口条件

1. **禁止写方自审，仅限独立只读调起。** 写方会话、执行子代理、模型自动规划都调不动（`disable-model-invocation: true`）。发现同会话自动触发，停手，退出码 `3`（§八 的 `init` 已把「拒绝执行」定为 3：不执行且要人处理）。
2. **先换异构模型。** 判方与写方同模型，同一盲区会在评审里被放过（§7.4）。同模型立即停手并说明，退出码 `3`。
3. **材料齐了才开工。** 复核包要有 §7.4 左列四样：判据原文（含 `expect`）、`base..head`、运行输出与退出码、契约的 `scope` 与 `why`；**再加第五样「完成声称的原文」**——INV-14 规定复核包只许含五类且五类必须齐，少了它 V5（无越界）无判定依据。缺哪样先记下，不许先判后补。
4. **跨会话盲审强制剥离写方 `<think>` 与自述。** 强制剥离并忽略写方的 `<think>...</think>` 思维链、`reasoning_content`、上下文压缩摘要与自述总结辩词；计划、对话历史、草稿、其他契约也一律丢开（§7.4 右列），严禁拿写方自辩当 `pass` 的理由。

## 步骤

1. **清点材料。** 按 §7.4 左列逐项打勾，缺的文件名单独记成缺口清单。
2. **按固定顺序过五项。** V1 范围 → V2 可定位 → V3 无放水 → V4 无未覆盖 → V5 无越界（§七）。每项先写下可指认的位置（判据哪行、diff 哪处、输出哪段），再落作答值；指不出只许写 `fail` 或 `unknown`。
3. **V3 先查例外与防放水坏样本校准准则。** 有决策记录写明「原判据无效」的答 `pass`；按 Anthropic 式防放水坏样本校准准则执行零容忍：凡遇放宽断言、删用例、改容差、加跳过（§7.2），以及空操作凑绿（noop）、硬编码特例返回值应付单测、吞异常伪造 `0` 退出码、篡改冻结测试哈希或跨契约越界偷改，无论写方措辞多合理，**一律判 `fail`**；反之对无可达反例的纯代码风格差异不得臆造 `fail`。
4. **填 unknown 前先过 §7.3 两列。** 左列（材料缺、自相矛盾、超出可读范围）才能写，且必须写明缺哪份文件；落在右列就回去给 `pass` 或 `fail`。写不出缺哪份材料即 `invalid-abstain`，退 `3`。
5. **汇总。** 全 `pass` → `0`；任一 `fail` → `1`；无 `fail` 但有 `unknown` → `3`（§7.1）。**复核包被篡改（指纹链断）与材料自相矛盾都退 `2`**（§八 与 INV-10 明文禁将 2 降级为 1 或 3；虽与 §7.3 冲突，本卡严格按 §八 执行退 `2`，该项作答仍写 `unknown`，见 skill/10（调研/评审材料，不在公开分发包内） G-02）。
6. **凡判 `fail` 必填结构化反例 `proof`（`J-03`）。** 任一维度判为 `fail` 时，**强制必填**非空 `proof: { premise, executionTrace, conclusion }`（`premise` 指明判据前提，`executionTrace` 给出触发缺陷的具体输入与 `base..head` 执行路径行号，`conclusion` 写明可观察冲突；缺任一非空字段直接退 `3` 拒收无据挑刺；判 `pass` 可选填）。
7. **交结论与多模型平行共识。** 输出五项作答（`fail` 项附完整 `proof`）、总结论、缺口清单与退出码，禁改判据、改代码或推状态。关键交付可经 `donegate verify apply <packDir> --votes v1.json,v2.json,v3.json` 汇总异构票据，或用包外 `escapes-regression` 校准集自校。

## 出口判据

1. 五项各一行，作答值只出现 `pass` / `fail` / `unknown` 三词，出现第四种或少项即失败。
2. **凡判 `fail` 的项均附带非空 `proof`（含 `premise`、`executionTrace`、`conclusion`），缺任何字段即退 `3` 失败；且全程未引用写方 `<think>` 思维链或自述总结。**
3. **V2 按原定义查：每一条判据都要能定位到改动里的具体位置**，任一条指不出即失败（§七 V2）。
4. 每条 `unknown` 都写明缺哪份文件或材料，写不出的按 `invalid-abstain` 退 `3` 失败（§7.3）。
5. 退出码与结果一致：全 `pass` 却 `1`、有 `fail` 却 `0`、只有 `unknown` 却 `1`、材料自相矛盾却给 `1` 均算失败（§7.1、§八）。
6. 结论无改判据、改代码、推状态字句（§7.4）；记判方模型名备查，与写方同模型即失败。

## 业界做法参考

| 参考 | 做到哪一步 | 与它的差异 |
|---|---|---|
| superpowers 的 `requesting-code-review` 与 `code-reviewer.md`（F2 首选） | 派审阅只给需求与 `base..head`，明令不传作者会话历史与思维链。全覆盖 | 本卡换成 §7.4 给/不给清单，并强制 `fail` 附 `executionTrace` 反例证明 |
| AdaRubric（J4 首选） | 按任务现场生成评分维度并打分。部分覆盖 | 它让机器生成 rubric；本卡不许判方生成或改冻结判据 |
| Anthropic `defending-code` Canary 校准集与 7-Stage Review | 用已知正负坏样本校准审阅器并做 `Find → Verify` 反例验真。部分覆盖 | 本卡吸收坏样本零容忍准则与 `proof.executionTrace` 强制验证，保持只读不改码 |

**两个代价**（adr/015（调研/评审材料，不在公开分发包内））：改成 AdaRubric 式现场生成维度，在「冻结的判据与任务对不上」情境下每轮省约 1 次改判据重签（次数）；但同一改动两次判会得到不同维度，与判据冻结及哈希链（§八）冲突。本卡反向付：判据改一字就要重签，判据写坏时每轮多 1 次冻结签收（次数）。按同一量比，本卡选可重复那侧。
