# 节点契约 · 判方

写方递来复核包，你只答 `pass` / `fail` / `unknown` 三个值（这就是五项 rubric 的作答），没有第四个值，也不写「差不多」「建议再看看」。五项怎么判见 `../设计/02-规格.md` §七（7.1–7.4）；本卡只说三样：怎么操作、什么顺序、什么算过。

## 入口条件

1. **只能人手动调起。** 写方、子代理、模型自动规划都调不动（`disable-model-invocation: true`）。发现自动触发，停手，退出码 `3`（§八 的 `init` 已把「拒绝执行」定为 3 的先例：3 = 不执行且要人处理，不是事故）。
2. **先换模型。** 判方与写方同模型，同一处盲区会在评审里被判成 pass（§7.4）。同模型就停手并说明，退出码 `3`（同 `init` 的「拒绝执行」先例）。
3. **材料齐了才开工。** 复核包要有 §7.4 左列四样：判据原文（含 `expect`）、`base..head`、运行输出与退出码、契约的 `scope` 与 `why`；**再加第五样「完成声称的原文」**——INV-14 规定复核包只许含五类且五类必须齐，少了它 V5（无越界）没有判定依据。缺哪样先记下，不许先判后补。
4. **写方那一侧不看也不收。** 计划、对话历史、思路、草稿、其他契约都是 §7.4 右列不给的；递过来也丢开，不许拿它当 pass 的理由。

## 步骤

1. **清点材料。** 按 §7.4 左列逐项打勾，缺的文件名单独记成缺口清单。
2. **按固定顺序过五项。** V1 范围 → V2 可定位 → V3 无放水 → V4 无未覆盖 → V5 无越界（§七）。每项先写下可指认的位置（判据原文哪一行、diff 哪一处、运行输出哪一段），再落作答值；指不出来只许写 fail 或 unknown。
3. **V3 先查例外再定值。** 有决策记录写明「原判据无效」的答 pass；放宽断言、删用例、改容差、加跳过四种没有例外，一律 fail（§7.2）。
4. **填 unknown 前先过 §7.3 两列。** 左列（材料缺、自相矛盾、超出可读范围）才能写，且必须写明缺哪份文件或哪份材料；落在右列就回去给 pass 或 fail。写不出缺哪份材料，就是 `invalid-abstain`，退出码 `3`——那是判方失职。
5. **汇总。** 全 pass → pass / `0`；任一 fail → fail / `1`；无 fail 但至少一项 unknown → 不过（材料不足）/ `3`（§7.1）。**复核包被篡改（指纹链断）与判方材料自相矛盾，都退 `2`**——§八 把这两样都列在 2 下面，且 INV-10 明文不许把 2 降级成 1 或 3。**规格自己有一处冲突要说清**：§7.3 把「材料自相矛盾」列进可填 unknown 的左列（按 §7.1 该退 3），与 §八 的 2 直接打架；**本卡按 §八 与 INV-10 执行（2）**——但**那一项仍照实写 `unknown`**（unknown 是作答，2 是事故；见 [skill/10](../skill/10-规格缺口定论（技能版）.md) 的 G-02），并在结论里注明引的是哪一条——这是规格缺陷，不是判方可自由裁量的事。
6. **交结论。** 五项逐条一行 + 总结论 + 缺口清单 + 退出码。不改判据、不改代码、不推状态、不碰六栏总账与通过四分（写方侧，§三）。

## 出口判据

1. 五项各一行，作答值只出现那三个词：跑 `verify apply` 看记录，出现第四种作答或五项缺项即失败。
2. **V2 按原定义查：每一条判据都要能定位到改动里的具体位置**，不是只看 fail 那几项；任一条指不出即失败（§七 V2）。
3. 每条 unknown 都写明缺哪个文件或哪份材料：逐条查，写不出的按 `invalid-abstain` 记，退出码 `3`，本条失败（§7.3）。
4. 退出码与结果对得上：全 pass 却 `1`、有 fail 却 `0`、只有 unknown 却 `1` 都算失败（§7.1）；材料自相矛盾却给 `1` 也算失败（§八）。
5. 结论里没有改判据、改代码、推状态的句子：全文过一遍，出现即失败（§7.4）。
6. 结论里记一句判方模型名，**只为备查**——规格只要求「判方必须换模型」（§7.4），没有要求写进结论，所以「没写出处」本身不算失败；但**与写方同一模型即失败**。

## 业界做法参考

| 参考 | 做到哪一步 | 与它的差异 |
|---|---|---|
| superpowers 的 `requesting-code-review` 与 `code-reviewer.md`（F2 首选） | 派审阅时只给一句话摘要、需求、`base..head`，明令不传作者会话历史；还要求逐条列出「考虑过但不归本次审阅」的行为。全覆盖 | 它面向通用代码审阅；本卡把材料边界换成 §7.4 的给/不给清单，把显式弃判换成缺口清单加三值作答 |
| AdaRubric（J4 首选） | 按任务现场生成评分维度，按步 × 维度打分并给置信度。部分覆盖 | 它让机器生成 rubric；本卡不许判方生成或改判据。它的 v0.1.0 只有库与单测，本卡无实现，纯纪律 |
| AI Evals Toolkit 的 `eval-rubric` | audit 模式审别人写好的判据，另用人工标注算 TPR/TNR 再改 prompt。部分覆盖 | 它靠样本回流调 judge；本卡只判一次，不许自我校准 |

**两个代价**（[adr/015](../设计/adr/015-说现成做法不适用必须给两个代价.md)）：改成 AdaRubric 式现场生成维度，在「冻结的判据与任务对不上」这一情境下每轮省约 1 次改判据重签（次数）；但同一改动两次判会得到两组不同维度，与判据冻结、先后由哈希链给出（§八）冲突。本卡反向付：判据改一个字符就要重签，判据写坏时每轮多 1 次冻结签收（次数）。按「每轮多几次签收」同一个量比，本卡选可重复那侧。
