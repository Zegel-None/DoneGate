# runner · M-02 最小内核试水（**不是插件版**）

**它是什么**：一个只为「判据退出码必须由子进程直读、不许采信模型自述」而写的最小运行器。业主 2026-11-19 授权按 `skill/09` （私有仓）§10.2 的 **B** 方案试水，范围到 `06` 的 **M-02** 为止——**不碰**状态机（M-01）、总账（M-03）、证据三件套（M-06）。

## 用法

```text
node runner/run-criterion.mjs <contract.json> [--report <out.json>] [--compare <模型自述的 report.json>]
node runner/self-test.mjs        # 红测：造夹具、跑六种情形、断言退出码
```

退出码严格照 设计/02-规格.md（调研/评审材料，不在公开分发包内） §八 四值：

| 退出码 | 含义 | 本内核里由什么触发 |
|---|---|---|
| `0` | 通过 | 每条命令型判据的实测退出码都等于 `expect.exitCode` |
| `1` | 判定为否 | 至少一条不相等 |
| `2` | **确定出了问题（事故）** | `--compare` 发现模型自述的退出码与实测不一致 |
| `3` | 无法判断 | 契约读不出、命令为空、**命令跑不起来**（预检不在 PATH 且不是绝对路径）、超时 |

## 它为什么长这样：一条负结果

`06` 的 M-02 原话是「拿 `pnpm` / `npx` 跑判据，**退出码被吞成 0**——本机实测过」。**本轮在这台机器上重测，没有复现。**

同一批夹具（内层 `process.exit(1)`），从 Node 的 `spawnSync` 出发，七条路径全部保真：

| 调用方式 | 实测 status |
|---|---|
| `pnpm run fail`（`shell: true`） | 1 |
| `pnpm run fail`（`shell: false`） | `null` + `ENOENT`（pnpm 是 `.ps1`，不经 shell 起不来） |
| `pnpm exec node fail.mjs` | 1 |
| `pnpm --silent run fail` | 1 |
| `npm run fail` | 1 |
| `npx --no-install node fail.mjs` | 1 |
| `node fail.mjs`（对照） | 1 |

从 PowerShell 直接跑 `pnpm run fail` / `npm run fail` 也同样是 1。

**所以本内核不做「包装层调用即判红」**——那条规则的前提在这里不成立，硬做就成了「跑绿一次都跑不了的判据」，按本项目的纪律应当删掉。**它保留的是另一条能红的**：`--compare` 对账，模型说「跑绿了」而实测不是，就是事故退 2。

**这条负结果的处置**：M-02 的措辞需要按实测改写（要么降级成「退出码必须直读」这条永远成立的纪律，要么补一个能复现吞码的具体调用形态）。改的是**设计包与 `06` 的前提**，要走 `skill/04` 的勘误流程，**本目录不动它**，只在 06（调研/评审材料，不在公开分发包内） 的 M-02 行加实测注记。

## 红测（`node runner/self-test.mjs`）

| 案例 | 期望 | 实际 |
|---|---|---|
| 判据真绿 | 0 | 0 |
| 判据真红（读子进程退出码，不看自述） | 1 | 1 |
| 命令根本跑不起来 | 3（不是 1） | 3 |
| 混合：一条绿一条红 | 1 | 1 |
| 自述照实 | 1（不误报事故） | 1 |
| **自述把 1 说成 0** | **2（事故）** | **2** |

最后一格是它「必须能红」的证明：去掉 `--compare` 的对账逻辑，这一格立刻变绿，说明它守的正是那句「不许拿自述当证据」。

## 它不做的事（写明边界，免得被当成插件版）

- 不判状态、不算总账、不写证据三件套——那些要 M-01/M-03/M-06，未获授权。
- 不判「判据写得对不对」（那是门 3 与判方的事）。
- `--compare` 只比 `exitCode`，不比 stdout 内容；要比内容得另立判据。
